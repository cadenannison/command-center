# 0076. Compose builds the image in the `api` service only

Status: accepted

Context: `docker-compose.yml` put `build: .` and `image: command-center:local` in the shared `x-app` block, so every service (api, scheduler, normalizer, five workers) had its own build of the same image. Compose builds services in parallel, so eight builds of one tag could race on the same layers and the same tag (observed: `docker compose up --build` failed with `target worker-gmail: failed to solve: image "docker.io/library/command-center:local": already exists`; after the change, `docker compose build api` then `up --no-build` started all 10 containers and the api passed its health checks).
Decision: `build: .` moves from the shared block to the `api` service. The shared block keeps `image: command-center:local`, so every other service uses the image the api build tags and has no `build:` block. The run steps in `docs/distributed-mode.md` are `build`, then `up -d --no-build` (each with the `--env-file` of decision 0077).
Alternative: (a) Keep `build` in every service and rely on BuildKit's cache: the builds still start together and still write the same tag. (b) A separate `builder` service or a `docker build` step outside compose: one more thing to keep in step with the compose file, and `docker compose build` would stop being the one command. (c) Publish the image to a registry: far more than a single-machine setup needs.
Reason: one build, one tag, and the single-command `docker compose build` still works. The cost is that `up` needs the image to exist: on a fresh checkout `up` without a prior `build` may make the non-api services try to pull `command-center:local` (or may build it; Compose versions differ), so the doc says to build first and uses `--no-build` so a missing image is an error, not a surprise build. Not yet run: what Compose does with a missing image is expected behaviour, not observed.
Where: `docker-compose.yml` (`x-app`, `api`), `docs/distributed-mode.md` (How to run); tests `test_compose_build.py`. The loopback and `CC_BIND_ALL` checks in `test_compose_file.py` are untouched.
Revisit when: the image is published to a registry (then every service can pull it and `build` can go), or the compose file is used on a host that cannot build.
