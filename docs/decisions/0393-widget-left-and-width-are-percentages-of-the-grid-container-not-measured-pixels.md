# 0393. Widget left and width are percentages of the grid container, not measured pixels

Status: accepted

Context: `ui/e2e/dashboard-display.spec.ts` "text size 150 and zoom 130 cause no horizontal overflow" failed at 1100px with the popover closed, three runs of three (the agent cannot run Playwright; this is the working diagnosis, to be confirmed by a browser run). The grid placed every widget with inline pixel `left` and `width` computed from the container width that `useGridSize` measured, and those properties animate (`transition-[left,top,width,height]`, 240 ms). When the window shrinks, the old pixel values stay on the page until the observer fires and React re-renders, and then they animate to the new ones. In that window a widget at the right edge is wider than the viewport and `scrollWidth` exceeds `clientWidth`. Nothing in the CSS at rest overflows: the grid is `w-full`, widgets are absolutely placed and the widget card is `overflow-hidden`.
Decision: `cssRectOf` in `metrics.ts` writes `left` and `width` as `calc((100% - gaps) * cells / cols + gaps-in-cells)`, so they follow the container's own width at layout time and `x + w <= cols` puts the right edge at or inside 100% by construction, at every zoom (the zoom only changes the gap and row height). `top` and `height` stay in px (rows do not depend on width). A lifted widget is the base rect plus the pointer's travel (`moveX`, `growX`), with a resize floored at one cell. `rectOf` (px) stays for drag arithmetic and its tests. No overflow is hidden or clipped anywhere.
Alternative: `overflow-x: clip` or `hidden` on the grid or the body (rejected: it hides a wrong width instead of removing it, and clips the glow). Disable the transition while the window resizes (rejected: the stale pixel width would still be there for a render). Wait in the test until things settle (rejected: weakens what the test says about the page).
Reason: the layout of a width-dependent box should be done by the browser at layout time, not by a number from the previous frame.
Where: `ui/src/features/dashboard/metrics.ts` (`cssRectOf`), `dashboard-grid.tsx` (item and drop outline styles), `metrics-css.test.ts`. The spec's failure message now names the widest element (`expectNoHorizontalOverflow`).
Revisit when: a browser run shows the spec still failing (then the cause is another element, and the new message names it), or the grid moves to CSS grid.
