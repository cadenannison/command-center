# 0355. The server validates the layout document with fixed limits, and the UI sanitizer stays authoritative on read

Status: accepted

Context: Task R2 stores each dashboard's layout JSON (decisions 0331, 0350). The server must not store arbitrary data, but the layout rules (widget registry, compaction, source kinds) live in `ui/src/layout/` and must not be copied into Python.
Decision: `core/dashboards.py` accepts only a layout of version 1 (an integer, not `true`), at most 50 items and 64 KB of stored text, with the UI's own keys (`id`, `widgetId`, `x`, `y`, `w`, `h`, `pinned`, `sources`, `options`) and no others. x, y, w, h are strict integers: x 0 to 11, x + w at most 12, y 0 to 499, w 1 to 12, h 1 to 64. Item ids and widget ids match `^[A-Za-z0-9_-]{1,64}$` (the UI's pattern); source ids match `^[a-z][a-z0-9_]{0,15}$`, at most 12 per item, no repeats; item ids are unique. `options` is kept because the UI stores it, but its keys match a pattern, there are at most 20, and its values are booleans or integers only, so no free-form string is stored. Overlap, per-widget limits and the registry are not checked: the server stores what passes and the UI's sanitizer decides what to show. Every refusal is a 422 with a fixed text that never echoes the input (0023).
Alternative: Copy the widget registry into Python (rejected: two sources of truth, and a new widget would need a server release). Store any JSON up to 64 KB (rejected: the card forbids free-form strings and unknown keys). Drop `options` (rejected: the UI writes it, so every save would fail or lose data).
Reason: Bounded, pattern-matched data cannot carry a script, a secret or a large blob, and the UI already survives anything it reads.
Consequences: A 422 lists `loc`, and a bad key under `options` or `source_colors`, or an unknown field, puts that key text in `loc` (the shared handler, `api/errors.py`, is unchanged). These are layout keys the caller typed, never a credential value; values are never echoed. Redacting non-model `loc` segments in the shared handler is a separate api task. A new layout key needs a server change and a version decision. Option values that are strings or floats are refused until a widget needs them. The UI's own 200,000-character limit is now above the server's 64 KB; the server's applies to what is saved.
Where: `src/command_center/core/dashboards.py` (`Layout`, `LayoutItem`); `tests/test_dashboards_core.py`.
Revisit when: layout version 2, a widget option that needs a string or a float, or the registry moves server side.
