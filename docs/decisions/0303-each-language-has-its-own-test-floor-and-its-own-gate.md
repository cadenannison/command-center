# 0303. Each language has its own test floor and its own gate

Status: accepted

Context: `.test-floor` holds the Python test count, and `scripts/test-floor.sh` (CI and pre-push) fails when `mise run test:count` falls below it. That count is pytest's and cannot see Vitest tests. Without a floor on the UI side, a deleted UI suite or a "no tests found" run would pass.
Decision: The Python floor stays exactly as it is: `.test-floor`, `mise run test:count`, `scripts/test-floor.sh`. The UI gets its own: `ui/.test-floor` (a number, raised by the human in the commit that adds tests), `mise run ui:test:count` (prints the Vitest test count, the last line digits only), and `bash scripts/ui.sh floor`, run by `ui:check` and by the CI `ui` job, which fails when the count is below `ui/.test-floor`. The Playwright browser and axe cases are counted separately and are not in the floor until they run in CI without a server of their own. Like the Python floor (pytest's collected count), the UI count includes skipped and todo tests, so the floor catches deleted suites, not skipped cases; the reviewer and the no-skip rule cover those. Each language's gate checks only its own floor and never the other's number. `ui/.test-floor` is human-owned like `.test-floor`: the edit deny list in `.claude/settings.json` and CODEOWNERS list it.
Alternative: One combined floor of Python plus UI tests (rejected: a drop in one language could hide behind growth in the other, and the two counts come from different tools). A floor file in the repo root for both (rejected for the same reason). No UI floor until later (rejected: the suite is empty then, which is exactly when a silent zero is most likely).
Reason: A floor only protects a suite if the number it checks is that suite's own.
Consequences: Two numbers to raise. `ui:test:count` has to parse Vitest's output or its JSON reporter; the scaffold task fixes the exact command and tests the parse. Until `ui/` exists, `ui:check` and `bash scripts/ui.sh` skip with a notice, so `ui:check` can sit in `mise run check` and the CI `ui` job passes without running anything.
Where: `ui/.test-floor`, `mise.toml` tasks `ui:test:count` and `ui:check`, `scripts/ui.sh`, `.github/workflows/ci.yml` (the K1 guard patch, applied by the human); `scripts/test-floor.sh` and `.test-floor` stay as they are.
Revisit when: Playwright cases run in CI without extra setup (add their count), or a third language arrives.
