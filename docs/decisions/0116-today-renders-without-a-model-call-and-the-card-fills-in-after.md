# 0116. Today renders without a model call and the card fills in afterwards

Status: accepted

Context: Decision 0113 point 4 generated the first summary inside the Today page request. A slow or missing provider delayed the whole page, and with no stored summary every reload called the provider again.
Decision: (1) `summary_card(..., generate=False)`, which the Today page now uses, never calls the provider. With a summary stored for the day it is `ready` with that text; with none it is `generating`, and the fragment's `hx-trigger="load"` posts `/summary/generate`, so the result arrives after the page is up. (2) `SummaryService.cached(day)` reads the store only. (3) `generate` already returns a stored summary unless `refresh`, so a day is generated once, on first need. Regenerate stays an explicit button (`refresh=true`); a failure shows the fixed redacted message with Try again, as before. (4) `container.summary` stays None while disabled and the not-enabled card is unchanged (decisions 0037, 0112). (5) A day with no items gets the template, which is not stored, so that case is not cached; it needs no provider call.
Alternative: (a) Keep generating in the page request: simplest, but the page waits on the provider. (b) Generate in a background task at startup or after sync: no request waits, but it spends a model call whether or not anyone opens the page, and it needs a scheduler (decision 0053 chose first need).
Reason: The page is instant, the provider is called at most once per day on first need, and a failure cannot break the dashboard.
Where: `web/summary.py`, `web/pages.py`, `services/summary.py`; `tests/test_summary_nonblocking.py`. Supersedes point 4 of 0113 (and its Alternative (a)). Existing assertions that expected summary text in the first Today render were changed to fetch the result from `/summary/generate`: `tests/test_web_pages.py` (`test_today_shows_the_summary_block_when_the_container_has_one`, `test_today_still_renders_when_the_summary_provider_fails`) and, in the A2 file `tests/test_web_summary_card.py` (new and uncommitted), `test_an_enabled_page_shows_the_result_and_a_regenerate_button`, `test_regenerate_asks_the_provider_again`, `test_ollama_needs_no_key`, `test_a_provider_failure_shows_a_redacted_error_with_a_retry`.
Revisit when: a user wants the summary ready before they open the page, or the HTMX request fails often enough that the card should retry itself.
