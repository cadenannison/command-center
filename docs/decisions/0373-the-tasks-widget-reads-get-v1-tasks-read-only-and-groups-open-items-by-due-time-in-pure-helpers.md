# 0373. The Tasks widget reads GET /v1/tasks read-only and groups open items by due time in pure helpers

Status: accepted

Context: Card W1b. GET /v1/tasks (0370-0372) returns ranked items with reasons. The dashboard grid (0360-0363) showed a placeholder in every widget body.
Decision: Only the widget with id `tasks` renders the list; the other widgets that share the `tasks` kind (Canvas, LearningSuite, Owed replies, My tasks) and Needs me stay placeholders, because /v1/tasks has no source filter and showing every source in a Canvas widget would be wrong. The widget fetches through the typed client and TanStack Query (staleTime 30 s, refetch on window focus), makes no other request, and offers no complete, dismiss or edit action. Grouping and formatting are pure functions in `tasks-model.ts` with the clock as a parameter: open items go to Overdue (due before now), Due in the next 48 hours (up to and including exactly 48 hours), Later, and No due date (always last, always labeled); the server's order is kept inside each group; done items are hidden; empty groups are left out. Tiers come from the registry's declared thresholds through `tier()`: W1 title and priority pill, W2 adds due time (12-hour, local) and source dot, W3 adds the top reason (most points, first of equals). Height tiers show 3, 6 or all rows with a "+N more" line. Each row has a disclosure button (aria-expanded, aria-controls) that expands all reasons with their points as real text. A link is rendered only when it parses as http or https (opens in a new tab, rel noopener noreferrer, accessible name includes the title). Loading, empty, error (no data) and stale (a refresh failed, older data kept) map to the shell's existing states.
Alternative: Render the list in every widget of kind `tasks` (rejected: no source filter in the API, so Canvas would show Gmail items). Add a `source` query parameter now (rejected: an API change, outside a UI-only card). Treat exactly 48 hours as Later (rejected: "next 48 hours" reads as inclusive). Show group headings only from height tier 2 as the prototype does (rejected: an unlabeled undated row at tier 1 would break "always labeled").
Reason: Pure helpers keep the boundaries testable without a DOM; limiting to one widget id avoids showing wrong data.
Consequences: The Canvas, LearningSuite, Owed replies and My tasks widgets stay placeholders until /v1/tasks can filter by source. The estimate chip and workload bar in the spec's W2/H3 rows are not built (the API has no estimate). An item whose source string is unknown (such as `local`) gets the My tasks dot. `now` ticks once a minute so Overdue stays current.
Where: `ui/src/features/dashboard/tasks-model.ts`, `use-tasks.ts`, `tasks-widget.tsx`, `dashboard-grid.tsx`.
Revisit when: /v1/tasks gains a source filter or estimates, or the other task widgets are built.
