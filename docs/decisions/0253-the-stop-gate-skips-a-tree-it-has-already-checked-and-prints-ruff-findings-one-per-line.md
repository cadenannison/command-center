# 0253. The Stop gate skips a tree it has already checked, and prints ruff findings one per line

Status: accepted

Context: The Stop hook ran `check:fast` whenever `git status` was non-empty. The working tree is dirty for long stretches, so every turn, including a read-only one, paid for the gates and put up to 60 lines of old failures, with full ruff code frames, into the context.
Decision: `scripts/hooks/stop-gate.sh` computes a fingerprint of the tree (`git diff HEAD` plus a hash of every untracked file) and stores it in `.git/cc-stop-gate.sha` after the gates have finished (an interrupted run leaves no stamp and is retried). The diff is taken with `--binary`, and staged plus unstaged separately in a repo with no first revision yet. If the fingerprint equals the stored one, it exits 0 without running them. A failure is therefore reported once for that tree state; any edit changes the fingerprint and the gates run again. It sets `RUFF_OUTPUT_FORMAT=concise` for the run. Everything else is unchanged: the `stop_hook_active` loop guard, exit 2 on a failure, and failing open when `jq` or `mise` is missing.
Alternative: Record a fingerprint at the start of the turn with a UserPromptSubmit hook (rejected for now: it needs an edit to `.claude/settings.json`, and the end-of-last-turn fingerprint gets the same saving without one). Store the fingerprint per session (rejected: a new session in an unchanged tree would pay again). Run the gates only on a clean tree (rejected: it checks nothing in the usual state).
Reason: The gate exists to catch what a turn broke. If the tree is the same as when it last looked, nothing new can have broken.
Consequences: This weakens the old guard, which blocked every stop while the tree was red: a red tree is now reported once, and a later turn on the same tree stops green. That is the point (the old behaviour forced unrelated lint work into read-only turns), but it is a trade the project manager should confirm. A red tree left alone is not re-reported on the next read-only turn; CI and the pre-push hook remain the backstop, and `docs/STATUS.md` records known red gates. An edit made by the human between turns also changes the fingerprint and is checked. A write to `.git/` that fails leaves the old behaviour (the gates run).
Accepted by the project manager on 2026-11-10, with the trade-off in Consequences.
Where: `scripts/hooks/stop-gate.sh`, `tests/test_stop_gate_hook.py`.
Revisit when: The hook is moved to a UserPromptSubmit baseline, or the gates become slow enough that skipping on a fingerprint is not enough.
