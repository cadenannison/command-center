# 0402. Row actions and one Undo toast on the Tasks and Needs me widgets

Status: accepted

Context: Card A1b. The backend gained dismiss, snooze and restore beside check-off (0334, 0398, 0399, 0400); the UI had no control for any of them.
Decision:
- Done, Dismiss and Snooze are in the expanded state of a row, in the Tasks and Needs me widgets only. Both rows already expand (the title button has `aria-expanded`), so the three buttons sit under the reasons in the same panel (`ui/src/features/items/row-actions.tsx`). The Events, Week and Weather widgets stay read-only: an event is not something the person completes, and the card names two widgets.
- Snooze is a Radix DropdownMenu with `modal={false}`, portaled into the row's `<main>` (found with `closest("main")`, as the Display popover and the widget menu are, 0383, 0392). Three items: Later today, Tomorrow morning, Next week. There is no custom time (0399). Every button is named by its visible text.
- One hook, `useItemActions` (`ui/src/features/items/use-item-actions.ts`), built on TanStack `useMutation`: `done`, `dismiss`, `snooze(preset)`, `restore`. The success callback is on the mutation options, so it still runs after the row that started the action has left the list. It invalidates the `tasks`, `needs-me`, `history`, `events` and `agenda` key prefixes (not `summary`, see below); mounted queries refetch in place and a failed refetch shows the existing notice, not a reset (0375). The toast does not wait for the refetches. A failure shows a fixed text per action ("Could not dismiss it. Try again."), never the server's, and changes nothing.
- One toast (`ui/src/components/toast.tsx`), provided inside `<main>` by the shell. It reads "Dismissed.", "Marked done." or "Snoozed until tomorrow morning." plus the item title (`data-sensitive`, 0396) and an Undo button; Undo calls restore, which also clears a snooze. It closes after 6 seconds, stays while the pointer or focus is on it, and Escape closes it. A new toast replaces the old and cancels its timer, so a stale one never wins (0388). Two live regions stay mounted (polite status, assertive alert for errors); the visible box is hidden from assistive tech so nothing is read twice. When the action came from the keyboard (the focused element matches `:focus-visible`) Undo takes focus, because the row that held focus has just left the page. Without a provider (a widget in a test) `useToast` does nothing.
- The refetch does not include `summary`. 0381 says a summary request can call the AI provider and that only the summary's own Retry asks for it again; an item action does not override that. The summary shows the change when its own rules next fetch it (the project manager's ruling on the first version of this record, which had included it).
- One action at a time: while any item action is in flight anywhere on the page (counted with `useIsMutating` on one mutation key), Done, Dismiss and Snooze are disabled on every row and Restore on every History entry, so the toast always belongs to the last completed action. A toast's own Undo or Try again is not blocked, so it is never lost.
- When the toast closes under focus (Undo, Escape) focus moves to `<main>`, not to `<body>`. The live region ends in a no-break space on every other toast, so the same text twice in a row is a change and is read again.
Alternative: A modal snooze dialog (rejected: 0383, 0392). A custom snooze time (rejected: 0399). Undo as a second request type such as DELETE (rejected: restore is the one inverse the contract defines, and it is idempotent). A toast per action stacked on the page (rejected: one at a time keeps announcements in order). Radix Toast (rejected: its viewport and swipe handling are more than one line of text and one button need, and the 0388 rule is simpler to keep in our own timer).
Reason: The three actions share one hook and one toast, so every route to hide or complete an item behaves, announces and undoes the same way.
Where: `ui/src/components/toast.tsx`, `ui/src/features/items/`, `ui/src/features/dashboard/tasks-widget.tsx`, `needs-me-widget.tsx`, `ui/src/shell/app-shell.tsx`.
Revisit when: events or the week widget get actions, a custom snooze time is added, or a second kind of notice needs the toast.
