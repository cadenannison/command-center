# 0289. The stop gate says on stderr when a missing tool turns it off

Status: accepted

Context: `scripts/hooks/stop-gate.sh` ran `command -v jq || exit 0` and `command -v mise || exit 0`. On a machine without either, every turn ended with no gate and no sign of it, so a red tree could be reported as done and nobody would know the gate was never running.
Decision: When `jq` or `mise` is not on PATH the hook prints one line to stderr and still exits 0: `stop-gate: skipped, <jq | mise | jq and mise> not found on PATH, so the fast gates did not run`. It names only the tools that are missing. It does not exit 2: the hook's exit 2 means "keep working, the gates failed", and a missing tool is a setup problem the agent cannot fix by editing code; blocking every stop would trap the session. It prints before the other checks, so a clean tree also shows the line (the gate is off either way). New tests in `tests/test_stop_gate_hook_edges.py` cover the three missing-tool cases and a normal run printing nothing; the same file adds characterization tests, which passed against the old script, for an untracked file whose name has spaces and parentheses, and for two worktrees of one repo keeping separate stamps (`git rev-parse --git-path` gives each its own `cc-stop-gate.sha`, so an edit in one never hides a change in the other).
Alternative: Exit 2 when a tool is missing (rejected: it blocks every stop on a machine that cannot satisfy it). Say nothing and rely on CI (rejected: that is the silent state this fixes). Write the notice to a log file (rejected: nobody reads it). Also print a line for the other silent exits: the loop guard and the "tree unchanged since the last run" skip are intended and stay silent; `cd "$root" || exit 0` still exits silently when the project folder is unreadable, which is not covered here.
Reason: A gate that can be off should say that it is off, in the one place the human or the session already looks, without turning a setup gap into a failure.
Consequences: On exit 0 the harness may show a hook's stderr only in verbose or debug output (not verified here), so the line may not appear in a normal turn; it is still written and the tests pin it. If that proves too quiet, the next step is a visible notice through the hook's JSON output, which needs its own record.
Where: `scripts/hooks/stop-gate.sh`, `tests/test_stop_gate_hook_edges.py`.
Revisit when: The harness gives a hook a visible warning channel, or the silent `cd` exit bites.
