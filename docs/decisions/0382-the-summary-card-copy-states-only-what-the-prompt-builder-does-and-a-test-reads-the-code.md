# 0382. The Summary card copy states only what the prompt builder does, and a test reads the code

Status: accepted

Context: Decision 0333 requires every privacy line to match real behavior, with a wording test. What a summary provider receives is `core/summary.build_prompt`: per item `- [kind] title`, the title collapsed, redacted (`core/redact.py`, best effort, decision 0240) and trimmed to `ITEM_TEXT_LIMIT` (80) characters, plus ` (due YYYY-MM-DD)`. `SummaryService._events` drops email events unless `include_email` (`Settings.summary_include_email`, default false, an environment setting with no UI). The `Event` model has `has_note` (a flag) and no note text or body field, and the summary code never reads `raw`, `link` or notes (decision 0125).
Decision: The copy lives in `ui/src/features/dashboard/summary-privacy.ts` and is shown under a summary a provider wrote, expanded only: "Written by Gemini." (or Ollama; "Written by your AI provider." for any other name); "Written from each item's kind, a redacted title trimmed to 80 characters, and its due date only."; "Notes and email bodies are never sent."; "Email is left out unless it is turned on in the app's configuration." A `stored` or `template` summary shows none of these (the notice says what it is). The caption names the provider and never says where it runs: an Ollama address can be another machine (0333). `summary-privacy.test.ts` reads `core/summary.py`, `services/summary.py`, `core/schema.py`, `config.py` and `services/summary_control.py` and fails if: the limit is not 80, the title is not redacted before it is trimmed, `build_prompt` reads any event field but `kind`, `title` and `due`, the provider is sent anything but the prompt, `Event` gains a field that could hold note text or a body, the summary code references notes, bodies or `raw`, email is not skipped unless `include_email`, `summary_include_email` is not false by default, or a provider other than gemini and ollama is named.
Alternative: Copy copied from the Jinja card (rejected: see Consequences). Run the Python from the UI test (rejected: the UI has no backend and the card forbids Python changes); the test checks source text, so it proves the code says it, not that it ran.
Reason: A wrong privacy line is worse than none (0333).
Consequences: Notes on the existing Jinja copy (read only, not changed; backend and web are outside this card): (1) `_summary.html` says "Written from titles and due dates only." and "titles and due dates of your items, with addresses and numbers removed": it leaves out that the item kind (`[task]`, `[event]`, `[assignment]`) is sent too, and "removed" overstates a best-effort redaction (0240). (2) `sources.py` and `howto.py` say "email addresses and numbers redacted first": the same. (3) The caption "Written by X" uses the provider's name from the response; for a summary already stored for a day, `SummaryService.get` labels it with the currently configured provider, so an old day's summary can carry a newer provider's name (today's is cleared on a provider change, decision 0115, and this card only asks for today). Changing a line means changing its test, with a task card saying `tests: modify`.
Where: `ui/src/features/dashboard/summary-privacy.ts`, `summary-privacy.test.ts`, `summary-card.tsx`.
Revisit when: a provider type is added, `build_prompt` sends another field, or an in-app switch for `include_email` exists.
