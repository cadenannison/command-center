# 0087. The decision-index script is `scripts/gen_decision_index.py` and reads every supersession form

Status: accepted; supersedes item 1 and item 3 of 0082 where they name the script and how `gen_docs.py` loads it

Context: Task 4d, closing two open decisions of 0085. 0082 named the script `scripts/gen-decision-index` because the card then did, and loaded it with `SourceFileLoader`. A hyphenated, extension-less file is skipped by ruff and pyright by default. Its parser also misread two forms of the Status line without an error: "superseded by decision 0060" and "superseded in part by 0060" were read as having no replacement, and only the first "supersedes" clause of a line counted. Three tests asserted less than their names said.
Decisions:
1. **Renamed to `scripts/gen_decision_index.py`** (still executable, still `build_index`, `DECISIONS_DIR`, `INDEX_PATH`, `main`; the error prefix is `gen_decision_index:`). Ruff and pyright now check it (`pyproject.toml` already includes `scripts`). `gen_docs.py` still loads it as a fresh module on every call (now by its new path), not with a plain `import`, because `tests/test_gen_docs_decision_errors.py` sets `DECISIONS_DIR` on the module it gets back, and a cached module would keep that value for the rest of the run. `mise.toml` is unchanged: `gen:build` and `gen:check` already call `gen_docs.py`, which renders the index; the card's "update gen:build and gen:check" needed no edit there.
2. **"Superseded by" accepts** `superseded by 0060`, `superseded by decision(s) 0060`, `partly superseded by 0060` and `superseded in part by 0060`, with a list of numbers separated by commas, `and`, `, and` or `&`.
3. **Every "supersedes" clause counts.** A clause runs to the next `;`, to a `.` followed by whitespace (not a dot inside `` `x.y()` `` or at the end of the line), or to the `)` that closes a `(` opened before the keyword (so `accepted (supersedes 0001) and extends 0002` does not count 0002). Brackets opened inside a clause are balanced first.
4. **"(in part)"** is shown for a replacement when the replaced record's own status is not "superseded", or any line that names it says "in part" or "partly" (`superseded in part by`, `partly superseded by`, `supersedes ... in part`). A replacement named by both records is listed once, and is "(in part)" if either says so.
5. **Tests** (`tests/test_gen_decision_index.py`, edited under the card's allowance; the path is updated): the in-part test is split into the replaced side alone and the replacing side alone (before, both sides spoke, so either side's failure was hidden by the other), the comma-list test is parametrised over `and`, commas, `, and` and `&` for both "superseded by" and "supersedes", the both-sides test now checks both rows, and the real-records test compares each row's number and link with the file it came from instead of only the count. One test per misread: `by decision`, `in part`, `partly`, a supersedes clause that says in part, two `supersedes` clauses in one line, a bracketed clause. Nine of them fail against the previous script.
Alternative: (a) Keep the old name and fix the parser: leaves the file outside the linters. (b) A structured `Superseded-by:` field: better data, but AGENTS.md lets old records change only on their Status and Sources lines. (c) Import the module normally in `gen_docs.py`: see item 1.
Reason: a script that generates a committed file should be checked by the same tools as the code, and a misread that is silent is worse than a loud error.
Where: `scripts/gen_decision_index.py`, `scripts/gen_docs.py`, `docs/MAP.md`, `docs/generated/decision-index.md`, `tests/test_gen_decision_index.py`.
Revisit when: a record needs a supersession the forms above cannot say; or the Status lines become structured.
