# 0028. Sync replaces a source's events in the sync window

Status: accepted

Context: `SyncService` only upserted, so an event deleted or rescheduled at the source stayed in the store forever and kept showing in the agenda.
Decision: `EventStore.replace(source, window, events)` deletes the user's events of that source that match `window` (the rules of `query`: time is start else due, a span matches on overlap, undated events never match) and upserts `events`, in one transaction. `SyncService.sync` calls it with the sync window after a fully successful fetch and never after a failure, so an outage or a rejected token keeps the old events. Stored events outside the window are not pruned. Undated events are never deleted by `replace` (they cannot be matched to a window), so adapters must give every event a `start` or `due` (`adapters.md` rules 9 and 10). `delete_source(source)` removes every event of a source, dated or not. An event whose `user_id` or `source` differs from the arguments is a `ValueError` before anything changes; the `source` check is the judgement call: without it a stray event is stored but no later sync can ever prune it. `replace` returns the distinct events written, which is the "Synced N items" count.
Alternative: (a) Delete the source's whole set on each sync: loses events outside the window that the adapter was never asked about. (b) Let the service query then delete then upsert: three calls, not atomic, and the matching rules would be repeated outside the store. (c) Mark-and-sweep by `fetched_at`: needs a new column and a migration (there are none yet).
Reason: One port call keeps the rules in the store next to `query` (one `_matches_window` predicate in SQLite), is atomic, and a failed or partial fetch can never delete data.
Where: `src/command_center/core/ports.py` (`EventStore`), `src/command_center/storage/sqlite.py` (`replace`, `delete_source`, `_matches_window`), `tests/fakes.py`, `src/command_center/services/sync.py`; `docs/contracts/core.md`, `storage.md`, `services.md`, `adapters.md`.
Revisit when: A source returns undated items that must expire (add an expiry rule), the store gains a migration path (mark-and-sweep becomes possible), or an adapter can only return pages (a partial fetch would then need a different operation, not `replace`).
