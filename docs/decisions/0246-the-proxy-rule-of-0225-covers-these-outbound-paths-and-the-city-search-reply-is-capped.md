# 0246. The proxy rule of 0225 covers these outbound paths, and the city search reply is capped

Status: accepted. Extends 0225, which covered only `chat_http.post_json`.

Context: 0225 turned off `trust_env` for chat calls because a proxy in the environment (`HTTP_PROXY`, `ALL_PROXY`, the macOS system proxy) receives an http request in clear text and chooses where to connect. The same holds for the other calls that carry the user's text: the summary prompt to Ollama or Gemini, and the typed city to Open-Meteo. Separately, `weather_geocode` read the whole reply into memory (`client.get`) while chat had a 1 MiB streaming cap (0222).
Decision: `trust_env=False` is now set on exactly these outbound paths, and on no others:
- `adapters/chat_http.py` `post_json`: the OpenAI-compatible and Ollama chat providers (0225).
- `adapters/summary_ollama.py`: the Ollama summary client.
- `adapters/weather_geocode.py`: the client the geocoder builds for itself. A client passed in with `client=` is the caller's and is used as it is (the app passes none; tests pass their own).
- `adapters/summary_gemini.py` `_default_client`: every Gemini SDK client (summary, chat and the key check, which builds its client through `_default_client` too). `types.HttpOptions` accepts `client_args` and `async_client_args`, which the SDK passes to its httpx clients, so both get `{"trust_env": False}` (this turns off the proxy only: the SDK builds its own SSL context and still reads `SSL_CERT_FILE`, `SSL_CERT_DIR` and `GOOGLE_GENAI_*` variables, unlike `chat_http` where 0225 also drops `SSL_CERT_FILE`); the request timeout stays in `HttpOptions.timeout`. A test builds the clients and reads `trust_env` from the SDK's own httpx clients, which is a private attribute (`client._api_client`) that a new SDK version may move. The SDK can use `aiohttp` for async calls when that package is installed, and its aiohttp session is built with `trust_env=True` with no option to change it; `aiohttp` is not in `uv.lock`, so this path is not in use, and installing it would reopen this.
Not covered, and still reading the environment: `adapters/weather.py` (forecast), `ical_feed.py`, `ical_diagnose.py`, `canvas_client.py`, Gmail (`googleapiclient` and `google-auth` use their own transport), CalDAV (`caldav` library), `desktop/events_client.py` (the menu bar's calls to the local server) and Redis. They carry a feed URL, a Canvas token or an OAuth token rather than the agenda text or a prompt, and a user may need a proxy for them; each needs its own decision.
The city search reply is read as a stream and stopped at the same cap as chat: the counting moved to `adapters/http_cap.py` (`read_capped`, `MAX_REPLY_BYTES`, `ReplyTooLarge`), which `chat_http` and `weather_geocode` both call, so there is one implementation. The status is decided before the body is read, so an error page is never buffered. A reply over the cap is a `FatalError` with fixed text (`Open-Meteo city search sent a reply that is too large`), which the service reports as the usual redacted 502. A body that does not decode (`httpx.DecodingError`) is a `FatalError` (`... returned an unexpected response`), not "unreachable". `chat_http.MAX_REPLY_BYTES` still exists (it is imported from `http_cap`) and is read at call time.
Alternative: One shared client factory for every httpx caller (a bigger change, and it would turn proxies off for the paths above that may need them); leave the geocoder on `client.get` (a 1 MiB cap on the chat reply and none on a call to a third-party host); copy `_read_capped` into the geocoder (two caps to keep in step).
Reason: A call that carries the user's own text should not go through a proxy someone else configured, and no reply from a third-party host should be unbounded.
Where: `src/command_center/adapters/http_cap.py`, `chat_http.py`, `summary_ollama.py`, `summary_gemini.py`, `weather_geocode.py`; `tests/test_summary_provider_hardening.py`, `tests/test_chat_provider_hardening.py`.
Revisit when: A user behind a mandatory proxy or a private CA needs these paths (see the backlog item for chat, which then covers all of them), or the SDK exposes `trust_env` for aiohttp, or any of the "not covered" paths starts to carry agenda text.
