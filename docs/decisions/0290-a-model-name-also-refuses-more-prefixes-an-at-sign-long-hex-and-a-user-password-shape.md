# 0290. A model name also refuses more prefixes, an at sign, long hex and a user:password shape

Status: accepted; supersedes in part 0270 (the rules of `model_name_looks_like_api_key` and the 100-character limit)

Context: Review of 0270 found these key-shaped values accepted, stored and shown again as a model name: `fw_` and `sk_live_` keys, an AWS temporary key id (`ASIA...`), a 24 to 31 character hex string, an email address, and `user:pw1234567890`. Meanwhile a real hosted name, a Bedrock inference-profile ARN, was refused for being over 100 characters.
Decision: `core.chat.model_name_looks_like_api_key(name)` is also true when the stripped name (1) starts with `ASIA`, `fw_`, `sk_live_` or `sk_test_` (added to the 0270 prefixes); (2) looks like an email: one character or more other than `@`, then `@`, then a letter, letters, digits or `-`, a dot and a letter (`bob@example.com`, `bob@mail-server.example.com`); an `@` followed by anything else is a version marker and passes (`claude-3-5-sonnet@20240620`, `claude-3-5-sonnet-v2@20241022`, `gemini-pro@001`, `m@v2.1`) (amended after the first pass, which refused every `@`); (3) holds a run of 24 or more hex digits (`[0-9A-Fa-f]`, anywhere in the name; the single-run 32+ rule of 0270 stays); (4) holds a colon followed by a run of 10 or more letters and digits with at least one digit (the `user:password` shape). The length limit is 200, in `core` (`MAX_MODEL_NAME_LENGTH`) and the service (`MAX_MODEL_LENGTH`); the service's own "at most 200 characters" text still runs first. `@` stays in the characters the service accepts in a model name. The exemption for ARNs: a run is not a password when the name starts with `arn:`, the run is exactly 12 digits and the next character is `:`; that is the account id slot of an ARN (`arn:aws:bedrock:us-east-1:123456789012:...`). Nothing else is exempt: `user:123456789012:x`, an ARN whose 12-digit run ends the name, and 11 or 13 digit runs are refused. A refused value is never echoed, stored or shown again (unchanged).
Alternative: Refuse every `@` (the first pass; rejected: Vertex AI and other hosts name models `claude-3-5-sonnet@20240620`). Require a dot and letters after `@` only as letters (rejected: `bob@my-company.com` would pass; digits and `-` are allowed inside the first label). Require both letters and a digit in the password run (rejected: the card says "containing a digit", and `user:1234567890` is a plausible password). Exempt any all-digit run (rejected: a numeric password would pass). Exempt every name that starts with `arn:` (rejected: `arn:x:pw1234567890` would pass; the narrow slot costs one regex). Keep 100 (rejected: a real ARN is 101 to 130 characters).
Reason: Each rule is a shape no real model name has. `llama3.1:8b-instruct-q4_K_M`, `hf.co/bartowski/Llama-3.2-3B-Instruct-GGUF:Q4_K_M` and `qwen2.5-coder:7b` pass because the run after their colon is short or ends at a `-` or `_`. The wider limit costs nothing: a long name made of short runs is not a key.
Consequences: A model tag with a long alphanumeric word that holds a digit directly after a colon (for example `name:abcdef12345`) is refused; the user renames it. A name that holds 24 hex digits in a row is refused. Version names such as `claude-3-5-sonnet@20240620` are accepted, so a name saved earlier with an `@` version keeps working. A model name saved before this change that the other new rules refuse (for example a 24-hex run or `name:abcdef12345`) now makes `ChatSettings.config()` raise `ChatNotConfiguredError`, so chat shows the fixed "looks like an API key" text for a name the user saved earlier; it fails closed, nothing is echoed, and re-saving a different name fixes it. Keys with other shapes still pass (best effort, as before); the card's text says keys go on the key card.
Where: `src/command_center/core/chat.py` (`model_name_looks_like_api_key`, `_holds_password_shape`), `services/chat_settings.py` (`MAX_MODEL_LENGTH`), `web/ai_settings.py` (`_shown_model`, through `MAX_MODEL_LENGTH`); `tests/test_chat_key_shapes.py`.
Revisit when: A real model name is refused by the colon rule or the hex rule, or a key of another vendor is stored as a model name.
