# 0283. Redaction stays idempotent: runs are read back to their start, token runs are swept twice, a marker is never an email's local part

Status: accepted

Context: Decision 0261 requires `redact(redact(x)) == redact(x)`. The rules of 0280 and 0281 (dates, versions, phrases, spaced emails, comma phones, code-before-keyword) opened new ways for a first pass to leave text that a second pass reads differently. The 30000-example property runs found `1231123::1::`, `12345610:30::1`, `111112ff::1::`, `345345ff::1::`, `bob @ a.combob @ a.com`, `11/12localhost/x11/12PM11/12/2026PM2.4.1.7`, `801,555,1234,11/1211/12`, `::a.2026-11-092026-11-09`, `code4821PM4821`, `a [at]10.0.0.1[at]a(dot)a`, `801,555,1234,2.4.1.7`, `1111/12:11/1211` and `11/12-10:30-11/12`.
Decision: (1) An IPv6 candidate is refused when the run it belongs to started right after one of our markers; the run's start is found by reading back over every IPv6 character (hex, `:` and `.`), not just the match. A run that touches a marker on its right, or is glued to one, is left alone too. (2) The token-run rule is applied a second time after the IPv4 and key sweeps, because removing a dotted address can join two pieces into one run. (3) The spaced and the spelled email rules never take a marker as the start of their local part. (4) The 3-3-4 phone rule with `,` `*` `x` also refuses a following `,` plus a marker, as it already refused `,` and a digit. (4b) A marker is never one of the words between a code keyword and its digits (`code[number]PM4821` reads like `code4821PM4821`), and a separator is not joined to a following `H:MM` time or to `:[number]`, which is what a time becomes after its minutes are masked. (5) A code keyword followed by digits masks only a run of three or more digits (`\d{3,}`), so the `2` of `cvv2` is not taken for a code.
Alternative: Run the whole pipeline until the text stops changing (rejected: no bound on passes, and it hides rule bugs that the property test should expose). Drop the rules that cause the cases (rejected: they are what keeps agenda text readable, decision 0280).
Reason: A property test over generated text is the guard for "never leaks" (core CLAUDE.md); a second pass that changes the text means the first pass was not a fixed point and the rules disagree about the same characters.
Consequences: A marker glued to an IPv6-looking run keeps the run as written, so `[number]ff::1::` stays; this leaks nothing a provider can read as an address. The token rule costs one more linear pass.
Where: `src/command_center/core/redact.py` (`_starts_after_marker`, `_redact_ipv6`, `_SPACED_EMAIL`, `_PHONE_ALT`, `_CODE_WORDS`, `_DIGIT_GROUP`, `_DIGIT_RUN`, the second `_RUN.sub` in `redact`); rows and strategies in `tests/test_redact_agenda.py`.
Revisit when: A rule is added that can join two runs, or a property run finds a new counterexample.
