# 0203. The chat page and the AI routes are loopback only, and the page calls ChatService directly

Status: accepted. Extends 0165 and 0211 to the web pages.

Context: Chat sends the agenda to a provider and the AI card holds provider addresses, so a paired phone must reach neither (0165, 0106). The page needs HTML back, and `POST /v1/chat` answers JSON. The web layer may import services but not the API.
Decision: `GET /chat`, `POST /chat/message`, `/chat/context`, `/chat/new`, `PUT /ai/settings` and `POST /ai/test` carry `require_loopback`, so a phone, a proxied request or an unclassified one gets 404. In the policy table `GET /chat` is HIDDEN (the page's own check answers) and the five writes are DENIED. The Chat nav link is drawn only when `loopback` is true, and the address, kind and model of the provider are on `/settings` only, which is already 404 for a phone; `GET /v1/settings` does not carry them. Sending goes through `ChatService.reply` with the API's status mapping, so the global htmx error listener (0212) shows a fixed `detail` in the panel's `.flash`. "New chat" calls `DELETE /v1/chat/{id}` as asked. htmx adds `Content-Type: application/x-www-form-urlencoded` to every non-GET request, which the API refuses for a write (0060), so the button removes that header in an `hx-on::config-request` handler, then posts `/chat/new` after a 2xx or a 404 (a conversation lost in a restart). Nothing is added to `test_json_only_writes.py` or `test_cross_site_writes.py`: they cover `/v1` writes only and no `/v1` route was added. The new rows are in `tests/test_remote_policy.py` only.
Alternative: Reuse `POST /v1/chat` from the page (the reply is JSON, so it needs client script to render it); a check in each handler (a second place that decides who is remote); a web `DELETE /chat/{id}` (the card names the API route).
Reason: One loopback check shared with `/pair` and `/settings`, and the service stays the only thing that decides what is sent.
Where: `src/command_center/web/chat_page.py`, `web/ai_settings.py`, `templates/_chat_parts.html`, `base.html`; `tests/test_web_chat.py`, `tests/test_remote_policy.py`.
Revisit when: A CSP is added (the `hx-on` handlers are inline script, as is 0212's listener), or the phone gets its own chat.
