# 0130. History is permanent: an item the source reopens keeps its completion and is tagged reopened

Status: accepted, its limitation and open question superseded by 0131. Supersedes 0129.

Context: Decision 0129 cleared a source completion when the source reported the item open again, so the completion vanished from history. The project manager ruled that history must be permanent: what was completed on a day stays on that day, even if the source later takes it back. The agenda must still show an item the source reopened as open (0129's reason: a wrong "done" must not hide an open assignment).
Decision: A new nullable column `item_ledger.reopened_at` records when a sync first saw a source-completed item come back open. `record_sync` (`_mark_reopened`) sets it on rows with `done_by = "source"` and no `reopened_at` whose item is returned with a status other than `done`; it never clears `done_at` or `done_by` and never touches a user check-off (`done_by = "user"`). `GET /v1/history` lists the item on the day of its (first) completion with `reopened: true` on the entry (`LedgerEntry.reopened`, only ever true in `done_by_source`); entries for a user check-off and for an item still done are `false`. The agenda shows the item open because `overlay_marks` now forces status done only for a user check-off; a source completion no longer forces anything, so the event's own status (the source's word) decides. `ensure_ledger_schema` adds the column at startup to a table made before this decision (`ALTER TABLE ... ADD COLUMN reopened_at`, SQLite and Postgres, a lost race re-checks and carries on); existing rows get NULL, which reads as "not reopened".
Limitation: a row holds one completion. If the source completes the item again after a reopen, the first completion time is kept (history for the earlier day keeps its entry, as required) and no second entry is made for the later day; the entry stays tagged `reopened` although the item is done again, and `reopened_at` is not cleared. The agenda is right (the source says done, so it shows done). Only the history of the second completion is missing.
Alternative: Clear the completion on reopen (decision 0129, now superseded; loses history). A `completions` table with one row per completion, so a second completion is its own entry on its own day (more tables, a migration of the sparse-row rules in 0120, and a question about what "done by you" means for several completions; revisit if re-completion history matters). Update `done_at` on re-completion (moves the entry to the new day, which breaks permanence).
Reason: `reopened_at` next to the kept completion is the smallest change that makes history permanent and still tells the reader the source took the completion back. The re-completion gap is rare (a graded assignment reset and resubmitted) and costs one missing history line, not a wrong agenda.
Where: `src/command_center/storage/sqlite_ledger.py` (`LedgerRow.reopened_at`, `ensure_ledger_schema`, `_mark_reopened`), `src/command_center/storage/sqlite_items.py` (`history`), `src/command_center/core/ledger.py` (`LedgerEntry.reopened`, `overlay_marks`); tests in `tests/test_ledger_sync.py`, `tests/test_ledger_migration.py`, `tests/test_items_ledger_api.py`, `tests/test_core_ledger.py`. Mobile contract: `reopened` is an additive field on history entries (`docs/mobile-api-notes.md`).
Revisit when: History must show every completion of an item that was completed more than once; then move to a completions table.
