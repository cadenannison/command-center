# 0394. The app is wrapped in a shell layout route with a collapsible left rail and a not-found view

Status: accepted

Context: Card S1. The UI had a text nav in a header and one page per route. The product needs a persistent navigation, and the Display popover (0391, 0392) must stay reachable from every page.
Decision: The root route renders `AppShell` (`ui/src/shell/app-shell.tsx`): a titlebar `<header>` (app name, the Display button, and on `/today` only the legacy theme switcher), a left rail `<nav aria-label="Main">` and `<main>`. The Display popover portals into `<main>` and stays non-modal (0383, 0392). Rail order: Menu toggle (`aria-expanded`), then Today (`/dashboard`), Chat, History, Focus; at the bottom Privacy (a toggle, `aria-pressed`) and Settings. There is no "Design rules" item: that page is a prototype reference and does not ship. Each item's accessible name is its visible text; collapsed, the text gets `sr-only` and no `aria-label` is used (axe label-content-name-mismatch). The active link carries `aria-current="page"`. Collapsed state is kept in localStorage under `cc-rail-collapsed`, every read and write in try/catch, as a per-browser convenience only. `/` and the production `/gallery` redirect to `/dashboard`. `/today` stays as a route (no rail item) until cutover. Unknown paths render `NotFoundPage` with a link to `/dashboard`. No new global keyboard shortcut was added. The lint rule that bans `localStorage` (AGENTS.md rule 7, `eslint.config.js`) blocks this flag, so `rail-state.ts` is the one file that touches it, with a visible `eslint-disable-next-line` on each access naming this decision; it stores "1" or "0" only. The tests reach it through that file's helpers. The project manager may prefer to allow-list the file in `eslint.config.js` instead.
Alternative: A rail that stores its state in display settings (rejected: needs an api change, and the state is per device). A top nav only (rejected by the card).
Reason: One layout owns landmarks and the Display button, so pages do not each place them.
Where: `ui/src/shell/` (`app-shell.tsx`, `rail.tsx`, `rail-state.ts`), `ui/src/router.tsx`, `ui/src/shell/app-shell.test.tsx`, `ui/e2e/shell.spec.ts`. `DashboardView` no longer renders the Display button.
Revisit when: the Chat, History, Focus and Settings pages exist, or `/today` is removed at cutover.
