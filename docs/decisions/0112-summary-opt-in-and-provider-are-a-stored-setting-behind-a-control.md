# 0112. The summary opt-in and provider are a stored setting behind a SummaryControl

Status: accepted; refines 0037 and 0053 (the service is still None while summaries are off)

Context: Task A2 makes the enable switch and the provider choice (gemini or ollama) changeable in the UI, with the environment value as the default. Decisions 0004, 0037 and 0053 rest on one fact: with summaries off there is no service and therefore no provider, so nothing can be sent. A runtime switch must not weaken that.
Decision: `services/summary_control.py` adds `SummaryControl(store, build, *, default_enabled, default_provider)`. It reads two keys (`summary.enabled`: `on` or `off`, and `summary.provider`) from the `AppSettingStore` port (0111); an unset key falls back to the environment default, a garbled switch counts as off, an unsupported stored provider falls back to the default. `service()` returns None while off and otherwise builds the `SummaryService` for the chosen provider once, through a builder the composition root passes in (services import no adapter), and reuses it until the provider changes. `Container` gains `summary_control` (default None) and `async summary_service()`: the control's service when there is a control, else `summary`. The api summary route and the web card call `summary_service()`, never `summary`. `app.build_container` still sets `container.summary` only when the environment says enabled (so the two `is None` tests and 0037's 404 stand) and shares that instance with the control for the configured provider. `summary_model` applies to the configured provider only; a provider chosen in the UI uses its adapter's default model.
Alternative: (a) Always build the service and give it an `enabled` flag: a second place for the opt-in to be wrong and a provider object that exists while off (rejected in 0037 (c)). (b) Mutate `Container` or rebuild it on a switch: the container is frozen and shared with the running app. (c) Keep the environment variable as the only switch: no way to opt in from the UI, which the card asks for.
Reason: The decision to send is taken in one method that returns None when off, so "disabled means nothing is sent anywhere" holds by construction, and a summary switched off after startup stops at once even though `container.summary` was built at boot. Store reads run through `asyncio.to_thread`.
Where: `services/summary_control.py`, `services/container.py`, `services/errors.py` (`UnknownSummaryProviderError`), `api/summary_routes.py`, `app.py`; `tests/test_summary_control.py`, `tests/test_web_summary_card.py`.
Revisit when: more settings join the store (a typed settings object), or workers need the same switch (they build no summary today).
