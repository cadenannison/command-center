# 0202. The AI card checks the address itself, holds the "turn chat on" switch, and owns the provider how-tos

Status: accepted. Fulfils the "revisit" of 0172.

Context: `normalise_provider` already refuses a bad address but replaces the reason with one generic sentence. The task asks for the fixed-text reason from `core/urlcheck`. Nothing in the web layer could turn chat on, and the environment variable is the only other switch. The provider, address and model are already stored app settings (decision 0161), so nothing is added to `storage/sqlite_app_settings.py`.
Decision: `PUT /ai/settings` runs `require_chat_base_url` on the address first (not for Gemini) and shows its message ("Rejected URL: ..."), which never contains the address; then `ChatSettings.set_provider` validates the whole block again and stores nothing when it refuses. The card also has a "Turn chat on" checkbox saved with the form through `set_enabled`; without it chat could be switched on only by an environment variable. After a refusal the form shows what was typed (non-secret values survive), except an address that carries a user, password, query or fragment, which is blanked so a credential is never echoed. The three how-tos (Ollama, LM Studio or llama.cpp, Gemini) are in `web/howto.AI_HOWTOS` and use the same `details.howto` markup as the source cards. The key stays on the "Chat provider key" card; this card links to it. The routes are `/ai/settings` and `/ai/test`, not `/settings/ai`, which the `/settings/{source}` routes would match.
Alternative: Show only the service's generic sentence (the user cannot tell which rule failed); leave "turn on" to an environment variable (no way to opt in from the UI); a `SOURCE_FORMS` entry with these fields (the card is not a credential source and would be swept into key handling); echo the typed address always (a credential would come back).
Reason: The user sees why an address is refused, can opt in where the opt-in is explained, and no secret is echoed.
Where: `src/command_center/web/ai_settings.py`, `web/howto.py`, `templates/_ai_card.html`; `tests/test_web_ai_settings.py`.
Revisit when: The key moves onto this card (0172's alternative), or the summary provider settings are unified with these (backlog).
