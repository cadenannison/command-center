# 0241. A token is 32 or more characters, or 24 or more with a digit, judged per part

Status: accepted; supersedes in part 0089 (the token rule); superseded in part by 0261 (a digits-and-separators run is not a token)

Context: The old rule masked a run of 24+ characters from `[A-Za-z0-9_-]` only when it held a digit, so `AKIAIOSFODNN7EXAMPLE` (20), `ghp_` plus 36 letters, base64 without a digit and any letters-only key passed. JWTs and keys joined by "." or "/" had only their long middle masked. The card's gap list says "any 24+ char letters-only token" but its rule 3 says 32+ for a token with no digit.
Decision: (1) Known prefixes are masked with their tail: `AKIA` + 16, `ghp_ gho_ ghu_ ghs_` + 16 or more, `github_pat_` + 16 or more, `sk-` + 16 or more, `xox[baprs]-` + 8 or more, `AIza` + 20 or more, and a JWT (`eyJ` header, ".", payload, optional ".", signature). (2) Other tokens: a maximal run over `[A-Za-z0-9_+/=.-]` (24+ long) is a token when any of its parts (split at "." and "/") has a digit and 24+ characters from `[A-Za-z0-9_+=-]`, or has 32+ such characters with at least one letter or digit; the whole run is then masked, so the head and tail of a joined token go too. A run with no "." and 32+ characters is base64 and is masked whole when it holds a "+" or "=", or a digit together with an upper- and a lower-case letter (`wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`). A trailing "." stays as punctuation. (3) The card's rule is followed, not the gap list: a digit-free run of 24 to 31 characters is NOT masked.
Alternative: 24+ for letters-only too (rejected: the card says 32+ and says not to mask ordinary long words; 24-letter words and 25-character hyphenated phrases are rare but real). Judge the whole run's length instead of its parts (rejected: `src/command_center/core/redact.py` is 33 characters of ordinary path and would be masked; the card says long URL paths without a token stay).
Reason: Parts keep file paths, dotted names and slugs readable while still catching a token hiding inside them.
Consequences: Known false positives: a hyphenated or underscore-joined phrase of 32+ characters with no space (a slug, `a_very_long_snake_case_identifier_name`), and a single 32+ letter word. Known false positives: `C++/Python/JavaScript/TypeScript` (32 characters, a "+" and no ".") reads as base64 and is masked, kept on purpose because a narrower rule would let a real base64 key through; a 32+ character path with no ".", a digit and mixed case (`src/Command_Center/api2/Routes_v1/x`) reads as base64. Known gaps: a base64 string with no digit, no "+" and no "=" whose parts are each under 32 is not masked; a letters-only key of 24 to 31 characters with no known prefix is not masked. Existing tests that used a long letter run as trim filler (`"x" * 500`) now see `[token]`; their filler was changed to spaced text, assertions unchanged (listed in the task report).
Where: `src/command_center/core/redact.py` (`_KEY`, `_RUN`, `_PART`, `_is_token_run`), `tests/test_redact_gaps.py`.
Revisit when: A real key shape of 24 to 31 letters turns up in logs or the false positives on slugs cost too much context.
