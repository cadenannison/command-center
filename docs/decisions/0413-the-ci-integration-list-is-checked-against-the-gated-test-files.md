# 0413. The CI integration list is checked against the gated test files

Status: accepted

Context: the integration job in `.github/workflows/ci.yml` runs a hand-kept list of test files against real Postgres and Redis. Twelve files whose cases skip without `CC_TEST_POSTGRES_URL` or `CC_TEST_REDIS_URL` were not on it, so they had never run against a real backend in CI (audit Q02; card 12). The audit and card counted seven; the real number was twelve, found by running the suite with both variables unset and reading which files skip citing them.
Decision: `tests/test_backend_ci_list.py` computes the gated files and the files on the integration job's list, and fails on any difference, printing both sides. A file is gated if its text names either variable, or it imports `DATABASES`, `REDIS_URL_ENV`, `POSTGRES_URL_ENV` or `redis_harness` from a `tests/*_support.py` module. Helper-only imports of `sink_support` or `ledger_support` do not count: about 40 files import them without being gated. The detector was checked against the facts: its 21 files equal the 21 files that cite a backend variable in a skip reason with no backend set. The workflow list now holds those 21.
Alternative: a pytest marker on gated tests (the audit's suggestion). Not taken: it needs `pyproject.toml` and the existing support files edited, and a missing marker fails silently, where a text comparison needs neither. Also not taken: the card's first rule (any import of a support module that names a variable), which flagged 55 files.
Reason: a list kept by hand drifts the moment a gated test is added, and the skip hides the drift.
Consequences: the comparison is textual. It reads `from x_support import NAME` and `x_support.NAME`, and only the `integration:` job's `run: >-` steps. It can be fooled by an indirection such as a gating symbol re-exported under another name, a variable name built from parts, or a changed step style (a `run: |` step makes the list empty, which fails loudly); the skip-reason cross-check above is the way to re-validate it. The twelve added files have never run on real backends; a failure on the first CI run is a new finding, not a reason to drop a file from the list. A new gated file now fails `mise run test` until it is added to the list.
Where: `tests/test_backend_ci_list.py`; the list in the `integration` job of `.github/workflows/ci.yml`.
Revisit when: a gated test uses a gating symbol the detector does not know, or the support modules are restructured.
