# 0392. The Display popover is non-modal, shortcuts are undo and redo in edit mode, and reduced motion is read-only

Status: accepted

Context: Card E2. The dashboard header needs one control for the display settings, the shortcuts setting needs its first users (0384 left undo and redo waiting for it), and the spec says reduced motion follows the system.
Decision:
- The control is a Radix Popover (`modal={false}`) opened by a "Display" button in the dashboard's top row and portaled into the page's `<section>` inside `<main>`, as the widget menu is (0383). It is a dialog named "Display settings"; Escape closes it and focus returns to the button; it never hides the rest of the page, locks scroll or injects a style. It holds theme (System, Light, Dark), zoom (70 to 130 in steps of 10), text size (90 to 150 in steps of 5), density (comfortable, compact: the two values the spec and `tokens.css` name), glow (0 to 1.6), high contrast, keyboard shortcuts and source colors (0390). Every control is a native input named by visible text; each change is announced in a polite live region inside the popover, and the save result in a status region (a failure is an alert). Width is `min(26rem, 100vw - 1rem)` with its own vertical scroll so text size 150 and zoom 130 cause no horizontal overflow (asserted in `ui/e2e/dashboard-display.spec.ts`).
- Reduced motion has no key: the popover shows one read-only sentence saying whether the system setting is on. `prefers-reduced-motion` keeps driving durations to 0s in CSS (0325).
- High contrast already exists in `tokens.css` (opaque surfaces, no blur, stronger hairlines, text 3 raised) from `tokens.json`; the contrast test covers its four modes. The shortcuts setting is on by default.
- Shortcuts: Ctrl or Cmd Z is undo and with Shift is redo, in edit mode only and only while the setting is on. One `keydown` listener is registered only in that state; with the setting off, or outside edit mode, no handler exists. The handler ignores a held key, Alt, an event another handler already took, any event whose target is in a text field, select or editable region (the browser's own undo belongs there) and any event inside an open dialog or menu. A one-line hint ("Shortcuts: Ctrl+Z undo, Ctrl+Shift+Z redo", ⌘ on a Mac) shows above the edit tools only in the same state.
Alternative: A modal dialog (rejected: 0383 and the card). A reduced-motion key (rejected: system only). Ctrl+Y for redo (rejected: one convention, no new shortcut beyond the two named). Hints on the Undo and Redo buttons (rejected: they would change the buttons' accessible names).
Reason: Non-modal keeps the dashboard readable and the screen reader's page intact; the narrow rules keep a global key from ever fighting a field, a dialog or a browser feature.
Where: `ui/src/features/display/display-menu.tsx`, `shortcuts.ts`; `ui/src/features/dashboard/dashboard-view.tsx`.
Revisit when: more shortcuts arrive (a registry would then replace the single hook), or the header gains a titlebar (the button moves there).
