# 0080. Four existing test files get a bounded wait, a deterministic collision test and engine disposal

Status: accepted

Context: Task 4a, "tests: new-only except the named files". `.claude/allow-test-edits` was used only for `tests/test_chaos_disconnect.py`, `tests/test_generation_store.py`, `tests/generation_support.py` and `tests/test_normalizer_atomic.py` (the last needed no edit, see item 4). Three problems: `until_fetching` could hang a run for ever if the worker never reached `fetch`; the "two first bumps racing" test usually did not reach the insert-collision branch of `SqliteGenerationStore.bump`, because a barrier at the start does not make both threads finish their first `UPDATE` before either inserts; and `sqlite_generations` opened engines that nothing disposed, so `-W error::ResourceWarning` failed `test_generation_store.py` (an unclosed `sqlite3.Connection`).
Decisions:
1. **`until_fetching(adapter, wait_seconds=5.0)`** wraps its yield loop in `asyncio.timeout` and calls `pytest.fail` with a message saying that no worker started fetching and why that usually means (job never consumed, or the worker died first). The loop still only yields (`sleep(0)`); the bound is a hang guard, not a delay, so the "no sleeping" rule of `.claude/rules/tests.md` holds. The parameter is not called `timeout` because ruff's ASYNC109 forbids that name on an async function. A new test in the same file runs the helper against an adapter nothing fetches from, with a 0.05 s bound, and asserts the failure message.
2. **The first-bump collision is tested deterministically.** `test_a_first_bump_that_loses_the_insert_to_another_process_updates_instead` listens to the store's engine with `before_cursor_execute`: when the store's own `INSERT` is about to run (its `UPDATE` already found no row), a second handle on the same file bumps first and creates the row. The store's insert then collides, takes the `IntegrityError` branch and its follow-up update returns 2. A result of 1 would mean the insert had won, so the test fails if the branch is not taken. Coverage of the module confirms the `except IntegrityError` path and the second increment run. The threaded `test_two_first_bumps_racing_both_land` is kept unchanged: it is still a valid check that two real threads never get the same number, it just does not claim to reach the branch.
3. **Engines are disposed.** `generation_support.sqlite_generations` records every store it opens and `close_sqlite_generations()` closes them (`SqliteGenerationStore.close` disposes the engine); `test_generation_store.py` calls it from an autouse fixture. A module-level list is used because the helper is a plain function called from tests and from a parametrised fixture, and `generation_support.py` is imported by other test files that never call it, so the helper keeps its signature.
4. **`test_normalizer_atomic.py` needed no change.** Its `stores` fixture gets the engine from `sink_support.open_engine`, which disposes in its generator's tail, and the fixture drives that generator to its end. Run with `-W error::ResourceWarning` the file is clean (8 passed, 8 skipped). The skipped cases are the Redis ones; the Postgres engines are created and disposed by the same `open_engine`, but no Postgres was available here, so that path was not run under the warning.
Alternative: (a) Convert the SQLite helper to a pytest fixture and rewrite the call sites: more churn for the same effect. (b) Replace the racing test: it would lose the real-thread check. (c) Stub `_increment` to force the collision: it would couple the test to a private function.
Reason: a hung CI run and a test that passes without testing what its name says are both silent failures; the ResourceWarning would become an error as soon as anyone enables `-W error`.
Where: `tests/test_chaos_disconnect.py`, `tests/generation_support.py`, `tests/test_generation_store.py`.
Revisit when: `filterwarnings = error` is added to pytest's config (then the three files are already ready), or the Redis and Postgres cases run in CI and show a warning.
