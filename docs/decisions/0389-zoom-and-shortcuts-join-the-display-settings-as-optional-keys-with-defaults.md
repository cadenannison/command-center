# 0389. Zoom and shortcuts join the display settings as optional keys with defaults

Status: accepted

Context: Card E2a. The UI needs two more persisted display settings: the dashboard zoom percent and whether keyboard shortcuts are on (0384 left undo and redo shortcuts waiting for such a setting). `DisplayInput` is strict (unknown keys refused, 0356), and `openapi.json` is the contract for a separate mobile repo, so any change to it must be judged for breakage.
Decision: `DisplayInput` gains `zoom` (strict integer, 70 to 130 inclusive, default 100) and `shortcuts` (strict boolean, default true). Both are optional on write: a PUT without them stores the defaults, and a stored document written before this change reads back with the defaults filled in, with no migration (the stored text is the JSON of `DisplayInput`, and pydantic fills absent keys). An out-of-range or wrong-type value is a 422 in the same shape as the other keys, and the input is never echoed (`hide_input_in_errors`). Unknown keys are still refused. Revisions, `If-Match`, the soft caps and loopback-only writes are unchanged, and so is the route policy table (same routes).
Alternative: Make both keys required on write (rejected: an older client's PUT would start failing 422, a breaking change). Add them to `app_settings` as separate keys (rejected: no whole-document revision, 0356). A stored schema version with a migration (rejected: defaults on read give the same result with no moving part).
Reason: Adding optional response fields and optional request fields with defaults is additive and non-breaking for the mobile client: an older reader ignores the new response keys, and an older writer that omits them still validates. One side effect is accepted: an older client that does a read-modify-write without the new keys resets zoom and shortcuts to their defaults, because the PUT replaces the whole document.
Where: `src/command_center/core/dashboards.py` (`DisplayInput`, `ZOOM_MIN`, `ZOOM_MAX`); `docs/contracts/api.md`; `tests/test_display_zoom_shortcuts.py`.
Revisit when: a third writer of display settings exists that cannot send every key (a PATCH route would then be a new decision), or the zoom range changes.
