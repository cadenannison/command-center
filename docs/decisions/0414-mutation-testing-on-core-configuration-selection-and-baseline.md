# 0414. Mutation testing on core: configuration, test selection and baseline

Status: accepted

Context: `mise run mutate` (`uv run mutmut run`, mutmut 3.8.1) never produced a result (audit Q01; card 13). Run unchanged, it warned that `paths_to_mutate` and `tests_dir` are deprecated, then stopped in the stats phase: `ERROR collecting tests/test_adapter_body_caps.py ... ModuleNotFoundError: No module named 'command_center.adapters'`, `failed to collect stats. runner returned 1`. Cause: mutmut copies only `source_paths` into `mutants/`, so the mutant tree held `command_center/core` alone while tests import adapters, services and storage; `tests_dir = ["tests/"]` then selected every test. A second obstacle, found by reading the config rather than by a failure: `addopts` carries `--cov-fail-under=80`, which no narrow selection can meet.
Decision: in `[tool.mutmut]` set `source_paths = ["src/command_center/"]` (whole package copied), `only_mutate = ["src/command_center/core/*"]` (only core is mutated), `pytest_add_cli_args = ["--no-cov"]`, and `pytest_add_cli_args_test_selection` to a path list of 33 test files. Selection rule: the file, and every `tests/` module it imports, imports from `command_center` only `command_center.core`, and neither reads repo-root files nor uses `TestClient`, `create_app`, `subprocess` or `__file__`. Mutation stays a by-hand task outside `mise run check`; `mise.toml` is unchanged because the task is `uv run mutmut run`, which reads all of this from `pyproject.toml`.
Alternative: a pytest marker on core tests (the audit's other suggestion). Not taken: it needs every file edited, and a missing marker silently drops a file from the measure; a path list is one visible place. Also not taken: running the whole suite under mutation, which fails on repo-root readers and takes far longer.
Reason: the selection is the only part that can silently weaken the score, so it is explicit and its exclusions are listed here.

Consequences: the baseline can inform, not gate, until a CI job exists. Wall time for a full core run is about 3.5 minutes, so a scheduled job is feasible. `uv run mutmut run` also writes `mutants/` in the tree (already gitignored). The selection is a hand-kept list: a new core test file is not measured until it is added.
Where: `pyproject.toml` `[tool.mutmut]`, applied by the human from the patch the agent prepared (not yet in `docs/audits/guard-patches/`; see the card report).
Revisit when: a CI job for mutation is added, `ports` and `chat` get selected tests, or the `tests/` layout changes.
