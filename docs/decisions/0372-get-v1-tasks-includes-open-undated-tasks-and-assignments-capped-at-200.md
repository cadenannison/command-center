# 0372. GET /v1/tasks includes open undated tasks and assignments, capped at 200

Status: accepted

Context: `GET /v1/tasks` (0371) read `EventStore.query(horizon)`, which only matches events with a start or due time (core contract), so an open task with no due time, such as a manual task the user typed in, never appeared. The project manager decided it should.
Decision: `EventStore` gets a narrow `undated_open(kinds, limit, *, user_id)`: events of kind `task` or `assignment` with no start and no due whose status is not `done`, newest `fetched_at` first (the only created-time column), then id, at most `limit`. `AgendaService.tasks()` calls it with a cap of 200 (`UNDATED_TASK_CAP`), applies the ledger marks, drops any item the user has checked off, and ranks it with the dated rows. Calendar events and email stay as they were. In `core/urgency.py` an open task or assignment with no due time gets one 0-point reason `no_due` ("No due date"); the existing +1 for a self-added task still applies, so a plain manual undated task scores 1 (priority 1; the card's first wording said 2, corrected by the project manager). No weight changed, so a dated item never scores lower than an undated one from the same source and a nearer due never lowers the score. Order stays priority descending, then due ascending with none last, then id. The cap is applied before marks, so a user-checked-off task uses a slot until the oldest rows fall out; an undated item the source marks `done` is excluded in the query.
Alternative: Widen `query` to return undated rows (rejected: it would change `replace`, which shares its rules and must never delete undated rows). Score an undated manual task 2 with a +1 undated reason (rejected: it would break "dated never lower than undated" for a manual task due beyond 14 days, which scores 1). No cap (rejected: the endpoint must stay bounded).
Reason: A separate read leaves every existing query and sync rule untouched; the cap keeps the response bounded.
Where: `core/ports.py`, `storage/sqlite.py`, `services/agenda.py`, `core/urgency.py`, `tests/fakes.py`, `tests/test_undated_tasks.py`.
Revisit when: more than 200 undated open items matter, a real `created_at` exists, or the UI needs a status filter.
