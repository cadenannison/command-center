# 0374. Edit mode keeps the widget title a heading with a separate drag handle, and focus moves to the read-only notice

Status: accepted

Context: The R3 accessibility review found two problems. In edit mode the whole header was `role="button"`, which hid the `h2` from heading navigation (recorded as a consequence in 0361). And if the window narrowed below 12 columns during a keyboard pick-up, the focused header unmounted and focus fell to `<body>`.
Decision: The header is a plain element holding the source dot, the `h2` and, in edit mode, a drag handle that is its own `<button>` beside the heading. The handle's accessible name comes from its content, not from an `aria-label`: a visually hidden "Move Events," followed by the visible tier badge ("W2 · H3 · 5×10"), so the name always contains its visible text (WCAG 2.5.3; axe label-content-name-mismatch stays on). Pick-up instructions stay in `aria-describedby`, and the word "widget" is carried in that description text ("Widget drag handle. Press Enter to pick up this widget...") instead of `aria-roledescription="draggable widget"`, because it is not certain axe accepts that attribute on a button and the sandbox cannot run Playwright to check. Keyboard pick-up, move, resize, drop and cancel live on the handle (aria-pressed shows it is held); pointer drag still starts anywhere on the header. When narrowing abandons a pick-up the grid announces it and then calls `onPickupAbandoned`; the view focuses `#dashboard-readonly` (now `tabIndex={-1}`) once that notice is rendered.
Alternative: Keep `role="button"` on the header and add `role="heading"` inside (rejected: nesting a heading in a button strips it). `aria-label` on the handle (rejected: easy to omit the visible text). `aria-roledescription="draggable widget"` (deferred until the human confirms with Playwright). Focus the Edit button instead of the notice (rejected: the card names the notice, and it explains why editing stopped).
Reason: Heading navigation works in edit mode and the handle is a real, correctly named button.
Consequences: Supersedes the header-as-button part of 0361 (its Consequences line about the heading). The handle's accessible name changed from "Events W2 · H3 · 5×10" to "Move Events, W2 · H3 · 5×10", so locators changed in the unit and Playwright tests. Pointer-only users can still drag from the whole header.
Where: `ui/src/features/dashboard/widget-shell.tsx`, `dashboard-grid.tsx`, `dashboard-view.tsx`.
Revisit when: the human confirms `aria-roledescription` passes axe on the handle (then it may replace the description wording), or a drag library is adopted.
