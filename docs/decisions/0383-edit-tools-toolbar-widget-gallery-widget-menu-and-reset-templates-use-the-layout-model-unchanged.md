# 0383. Edit tools: toolbar, widget gallery, widget menu and reset templates use the layout model unchanged

Status: accepted

Context: Card E1 adds the UI for logic that already exists in `ui/src/layout/` (`addWidget`, `remove`, `setPinned`, `resize`, history, templates). Decisions 0331, 0350 and 0360 to 0363 fix the model, 12-column editing and the save path; 0374 fixes the header (heading plus a separate drag handle).
Decision:
- Every change goes through `dispatch({ type: "apply" | "undo" | "redo" })` on the existing history reducer in `dashboard-view.tsx`; the existing effect hands `history.present` to the debounced `LayoutSaver`. Nothing in the save path changed. A test saves an add, an undo, a size preset and a template reset and checks the `If-Match` header on each PUT.
- Toolbar (`edit-toolbar.tsx`): a `group` named "Edit tools" with Add widget, Undo, Redo, Reset, Export and Done, rendered only when edit mode is on and the window has 12 columns. Below 12 columns the existing read-only notice applies and the toolbar is not rendered. The Edit button stays as the toggle; Done does the same and puts focus on Edit, because the toolbar it was on unmounts. This replaces the two Undo and Redo buttons that R3 placed beside Edit.
- Gallery (`widget-gallery.tsx`, `edit-model.galleryEntries`): a Radix Dialog (from the approved `radix-ui` package). A flat list (spec.md says grouped Overview, Tasks, Events, Other with source colors; not built, a follow-up), one row per `WIDGETS` entry in registry order: name, kind, one description line, default size, and how many are already on the dashboard. The description is the kind's sentence (a `Record<GridWidgetKind, string>`, so a new kind fails to compile until it has one) plus the widget's default sources; the registry itself gained no field. The default size is `preset("M", def)`, which is what `addWidget` uses.
- Duplicates: the registry has no one-per-dashboard rule. The only limits are unique item ids, at most 50 items (`MAX_ITEMS`) and nothing below row 500 (`MAX_Y`); the sanitizer would drop an item past either on the next load. So the gallery allows a second Events widget, gives it the next free id (`events-3`, never a number in use), and disables Add with the reason when a limit would be hit (`edit-model.addBlocker`).
- "First free spot" is `addWidget`'s behaviour: left edge, just below everything, then push-down compaction. It does not search the gaps; Auto-arrange is the tool for that.
- Selecting a widget closes the gallery and announces "Added Events at column 1, row 11, 4 wide, 8 tall." About 100 ms later, because an open modal hides the page, live region included, from assistive technology. Focus returns to Add widget (Radix). Escape closes it and adds nothing.
- Widget menu (`widget-menu.tsx`): a Radix DropdownMenu opened by its own button, "Options for <title>", in the header beside the drag handle and outside the `h2` (0374). Items: S 3×5, M 4×8, L 7×10, Pin or Unpin, Remove. A preset is disabled, with the reason as visible text in the item, when the widget is pinned ("Unpin it to resize."), when clamping to the registry's min and max would change it ("Weather is limited to 2×3 up to 6×9." for L on Weather), or when the widget already has that size. An enabled preset calls `resize` with `preset(name, def)`. Pin and Unpin call `setPinned`. Pinned widgets still cannot move or resize (0350).
- The menu sits inside the header, whose pointer handlers start a drag, and React bubbles events through a portal. The grid now ignores a pointer down whose target is inside `[data-no-drag]`; the menu button and the menu content carry it.
- The widget menu is non-modal (`modal={false}`) and portals into the dashboard section, inside the page's `<main>`, so it neither hides the page from assistive technology nor sits outside every landmark; its announcements are immediate. Remove puts focus on Add widget, since the menu button it came from is gone. Pin, Unpin and sizes leave focus on the menu button (Radix).
- Reset (`reset-dialog.tsx`): a confirm dialog with the four templates as radio buttons (each listing its widgets) and an Apply button that stays disabled until one is chosen. Applying dispatches `apply` of `DEFAULT_LAYOUTS[name]`, so it is one undoable step; the history's own `reset` action (back to the base layout) is not used because the card asks for templates. Applying the layout already shown records nothing and says so.
- Every action announces through the existing live region: add, remove, resize, pin, unpin, undo ("Undone."), redo ("Redone."), reset and export.
Alternative: Add a `description` field to the registry (rejected: the registry is the layout module's persisted vocabulary and the card keeps that module as it is; a per-kind sentence covers every widget). Search the gaps for the first free spot (rejected: it would add a second placement rule beside `addWidget` and compaction). Allow only one widget per id (rejected: nothing in the model requires it, and two Events widgets for two calendars is a sensible use). A hand-made popover for the menu (rejected: a 5-row dashboard widget clips an in-card panel, and Radix is already approved and gives menu keyboard behaviour). Preselect a template in Reset (rejected: a destructive default).
Reason: One dispatch path means undo, redo, saving and announcements cannot disagree between pointer, keyboard and the new controls.
Consequences: First use of Radix in the UI. OPEN FOR THE HUMAN, dialogs only: the gallery and reset dialogs are modal, and Radix modals use `react-remove-scroll-bar`, which injects a `<style>` element that the strict CSP (0301, `style-src 'self'`) will block once the header ships (not seen in a browser). The widget menu no longer has this problem because it is non-modal. For the dialogs the choice is a nonce, `modal={false}` (losing the focus trap), or accepting it in writing. The new Playwright spec `ui/e2e/dashboard-edit.spec.ts` was not run by the agent.
Where: `ui/src/features/dashboard/` (`edit-model.ts`, `edit-toolbar.tsx`, `widget-gallery.tsx`, `reset-dialog.tsx`, `widget-menu.tsx`, `dialog-parts.tsx`, `widget-shell.tsx` for the `menu` slot, `dashboard-grid.tsx` for `itemMenu` and `data-no-drag`, `dashboard-view.tsx`); tests `edit-model.test.ts`, `edit-tools.test.tsx`, `edit-save.test.tsx`; `ui/e2e/dashboard-edit.spec.ts`.
Revisit when: the registry gets a description field, a user wants the new widget placed in a gap, the CSP header ships and shows a violation, or free placement arrives (0331).
