# 0258. A key-shaped model name or address is refused using the redaction rule and three prefixes

Status: accepted; replaces the shape test of an earlier pass of this task (two patterns of its own, never recorded); superseded in part by 0270 and 0290 (the model-name test); extended by 0291 (the address rules stand and are added to)

Context: A user can paste an API key into the AI card's model or address field. Those fields are stored in plain app settings and shown again on the card, unlike the key, which goes to the keychain (rule 5). A key pasted there is stored in the clear and echoed back. An earlier pass added a shape test with its own two patterns (key prefixes plus an unbroken letters-and-digits run). The card for this task said to reuse the redaction rule and not add a second pattern.
Decision: `core.chat.looks_like_api_key(text)` is true when the stripped text starts with `sk-`, `AIza` or `ghp_`, or when `redact(text)` differs from it. It has no pattern of its own; what counts as a token, a number run or an address is decided once, in `core/redact.py` (0240-0244). `core.chat.address_holds_api_key(address)` applies the same test to each path segment of an address, as typed and percent-decoded, and, unless the host is an IP literal, to each dot-separated label of the host by `redact` alone (no prefix test, so `sk-llm-gateway.example.com` stays valid). Whole-host testing was tried and dropped: `redact` turns a bare `www.example.com` into `[url]` and masks an IPv4 address, so ordinary hosts and every LAN server would be refused. A key typed as the host would otherwise be stored in the clear, shown again and sent to a DNS resolver (found in review). A query, fragment or credentials in an address are refused by the address guard with its own text. A model name longer than 100 characters is refused before any test and never echoed. A refusal says "looks like an API key; keys go on the key card", never the value; nothing is stored. The AI card puts a refused value back only if it passes the same tests (`_shown_model`), and an address only if it parses as an http(s) URL with a host and has no credentials, query, fragment or key-shaped path segment (`_shown_address`); so a key pasted into the address field is never shown again, even in a field that failed another rule; a port that is not a number blanks the address too (a key typed where the port goes). A key-shaped model or address already stored is an unusable provider setting (`ChatNotConfiguredError`) and is never used or shown.
Alternative: Keep the two own patterns (rejected by the card; they must also be kept in step with `redact`, and they were a second place to be wrong). Test the whole address with the prefix rule too (rejected: `sk-` hosts are legal names; and an IPv4 address must be skipped, since `redact` masks it). Refuse only by prefix (rejected: most keys have no known prefix).
Reason: One rule for "looks like a secret" stays in one file. A false refusal is cheap to fix by the user when the name can be changed; a stored key is not recoverable once echoed.
Consequences: A real model name of 32 or more characters in one unbroken run of letters, digits, `-` and `_` is refused, for example `meta-llama/Llama-3.3-70B-Instruct-Turbo-Free` and `hf.co/bartowski/Llama-3.2-3B-Instruct-GGUF:Q4_K_M`, because `redact` treats a 32-character token as a key; `tests/test_chat_key_shapes.py` lists them. Such a user has no workaround on a hosted OpenAI-compatible server (an Ollama user can `ollama cp` the model to a short name). The check is best effort: a key of another shape, shorter than 32 characters and without a prefix, still gets through; the card's text says keys go on the key card. A host label of 32 or more characters, or of 24 or more with a digit, is refused as a host, and so is a dashed IP name with six or more digits such as `192-168-1-10.sslip.io` (a label masked as a number); `ip-10-0-0-5.local` (five digits), `10.0.0.5.nip.io`, `www.example.com` and a host that merely starts with `sk-` are accepted. A percent-encoded key in the path is caught by decoding each segment; encodings of other kinds (double encoding) are not.
Where: `src/command_center/core/chat.py` (`looks_like_api_key`, `address_holds_api_key`), `services/chat_settings.py` (`normalise_provider`, `_checked_address`), `web/ai_settings.py` (`_shown_address`, `_shown_model`); `tests/test_chat_key_shapes.py`, `tests/test_web_ai_settings.py`.
Revisit when: A user hits the long-name refusal for a real model: add an allow-list of model-name shapes, or accept names that match the `_MODEL` pattern and contain a `/` or `:` as a separator, in `redact`'s own token rule rather than here.
