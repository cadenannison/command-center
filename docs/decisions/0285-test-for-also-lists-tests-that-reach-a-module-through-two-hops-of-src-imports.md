# 0285. test:for also lists tests that reach a module through up to two hops of src imports

Status: accepted. Supersedes 0252 in part (only its rule that `test:for` lists direct importers and nothing else). Amended by the project manager's follow-up card on the same day (hub skip, line cap and ranking, below), by editing this record in place because 0285-0289 were all in use.

Context: 0252 made `scripts/tests_for.py` list only the tests that import the module themselves, and accepted that it "misses a test that reaches a module only through a rig or another module". That miss is real: for `core/redact.py` it printed 4 files and left out `test_connect_message_redaction.py`, `test_sync_message_redaction.py`, `test_core_chat.py` and `test_summary.py`, which exercise redaction through `services/errors.py`, `core/chat.py` and `core/summary.py`. An agent that trusts the short list can skip a test that would have failed.
Decision: (1) `tests_for.py` builds the import graph of `src/` (the same static rules as for tests: `import a.b`, `from a.b import x`, `from a import b`; relative imports are not used in `src/`). A test that imports a module which imports a target (one hop), or a module that imports one of those (two hops), is listed with ` (indirect)` after its path. A third hop is not followed. A test that also imports the target directly is listed bare, never as indirect. (2) Only a `test_*.py` file is listed as indirect: a rig or helper module (`fakes.py`, `web_rig.py`) cannot be run, so listing it only adds noise. A helper that imports the target directly is still listed bare, as before. (3) A target path that does not exist or is not a file is an error: a message naming the path on stderr, nothing on stdout, exit 1 (before, a typo printed nothing and exited 0, which read as "no tests"). (4) `tests_for()` keeps its direct-only result and signature; the new `find_tests()` returns `Hit(path, indirect, hops, breadth)` and the command prints from it. (5) A module that more than 25 `test_*.py` files import is a hub (`HUB_TEST_IMPORTS`) and is not a hop: it is neither counted nor followed through. The target itself is never skipped, and a helper module under `tests/` does not count toward the 25. (6) At most 15 indirect lines are printed (`MAX_INDIRECT_LINES`), followed by `+N more` for the rest; direct lines are never capped or counted in N. Which 15: the closest hop first (a test that imports a module that imports the target before one two hops away), then the test that imports the fewest src modules (a focused test before an app or wiring test), then path. The kept lines print in path order, so the list reads the same as before. `find_tests()` returns every hit; only the command caps.
Alternative: Follow imports to any depth (rejected: through `core/ports.py` or `app.py` every module reaches everything, so the list would be the whole suite). One hop only (rejected: `test_sync_message_redaction.py` and the like are two hops through a service). A flag to print direct importers only (not built: the mark makes the two kinds easy to tell apart, and `grep -v indirect` does the same). Keep the first 15 indirect lines in path order (the literal reading of the cap; rejected: for `core/redact.py` they were `test_api.py`, `test_app_*.py` and `test_chaos_*.py`, the widest tests, while `test_summary.py` and `test_core_chat.py` fell off the end). Count every file under `tests/` toward a hub (rejected: rigs and fakes import the common modules, so it would call a module a hub because of how tests are built, not how many tests need it). Print the indirect mark in a separate column or on stderr (rejected: one path per line stays easy to read).
Reason: Two hops finds the tests that named the gap in the review while staying a loop aid; the mark tells the reader which ones are a reach and which are a direct test of the module.
Consequences: The hub rule did little for `core/redact.py`: the hubs today are `core/errors.py`, `core/schema.py` and `core/windows.py`, none on its path, so it still reaches 93 indirect tests (47 through one hop, 46 through two) and the cap hides 78. The cap is what keeps the output short. With the ranking the 15 kept include `test_summary.py` and `test_core_chat.py` (one hop), but `test_connect_message_redaction.py` and `test_sync_message_redaction.py` (two hops, importing many modules) are in the hidden 78. The `+N more` line says some tests were left out, and the command has no way to list them (naming a nearer module such as `services/errors.py` does not help: it still hides 24); `grep -l` on the module name in `tests/` finds a specific one, and a flag that prints everything is the first thing to add if this bites. The path is not safe to pass straight to pytest (the suffix and the `+N more` line are not paths): filter them out, for example `grep -v -e ' (indirect)$' -e '^+'`, or take the bare lines only. The graph reads only static imports: a module loaded by name is not seen, an import inside `TYPE_CHECKING` is counted like any other, and a name re-exported through a package `__init__.py` counts only as an import of that package. `mise run check` still decides done.
Where: `scripts/tests_for.py`, `tests/test_tests_for_indirect.py`, `tests/test_tests_for_limits.py`, `AGENTS.md` (the `test:for` line).
Revisit when: The 25-file or 15-line limits prove wrong in use, an agent needs the full indirect list (add a flag), or tests move into subfolders.
