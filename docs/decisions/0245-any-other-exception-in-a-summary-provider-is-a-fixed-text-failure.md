# 0245. Any other exception in a summary provider is a fixed-text failure

Status: accepted. Brings the summary providers to what 0223 did for chat.

Context: `GeminiSummaryProvider.summarize` and `OllamaSummaryProvider.summarize` translated the exceptions they knew (SDK API errors, httpx errors) and let every other one through. The summary service logs `str(exc)` of a provider failure (`SummaryService._log_failure`) and the web layer shows the service's text, so the message of an unexpected exception (a bug in the SDK, a `ValueError` that echoes the prompt or the key) could reach a log line or a response. The Gemini summary path also built its client outside the `try`, and its `finally` closed the client with a bare `await client.aio.aclose(); client.close()`, so a failure while closing replaced the real outcome with an arbitrary exception.
Decision: Both providers end their `try` with `except Exception`, which raises `SummaryProviderError` with fixed text (`Gemini request failed`, `Ollama request failed`) `from None` and logs one warning with a reason code and the exception's class name only. `asyncio.CancelledError` is a `BaseException`, so it passes through. The Gemini summary path now builds its client inside the same guard, reads `response.text` inside it, and closes through the existing `_close` helper (which logs a cleanup failure by class and never replaces the outcome), like `GeminiChatProvider`. Tests: `tests/test_summary_provider_hardening.py` (an exception whose message holds a needle shows up in no raised text and no log record, only its class name does; a cancellation is not swallowed).
The SDK's default HTTP library is httpx2, whose `HTTPError` is not a subclass of httpx's, so `except httpx.HTTPError` never matched a real SDK network failure and the new catch-all would have turned "Gemini is unreachable" into "Gemini request failed". `_is_http_error` matches a network error by class name along the MRO (`HTTPError` from `httpx` or `httpx2`), in the Gemini summary, chat and key-check paths, so this module still needs no httpx2 import. Tests build real `httpx2` errors. Not done: `GeminiIntegration.validate` has no catch-all (an unknown exception there re-raises as before, and its `finally` still closes the client bare); that is a backlog item.
Alternative: Catch only the SDK's base exception (misses a `ValueError` or `KeyError` from inside the SDK); log `repr(exc)` for debugging (the thing being avoided); catch `BaseException` (would swallow cancellation and `KeyboardInterrupt`).
Reason: The adapter is the last place that knows what an exception might contain, so it is the place that drops the text. The class name is enough to debug from.
Where: `src/command_center/adapters/summary_gemini.py` (`summarize`, `_summary_failed`), `src/command_center/adapters/summary_ollama.py` (`summarize`); `tests/test_summary_provider_hardening.py`.
Revisit when: The summary providers are rebuilt on the chat port (backlog), which has the same catch in `chat_http` and `GeminiChatProvider`: then there is one place.
