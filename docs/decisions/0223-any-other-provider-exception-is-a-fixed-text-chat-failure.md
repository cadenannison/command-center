# 0223. Any other provider exception becomes a fixed-text chat failure

Status: accepted

Context: `GeminiChatProvider.complete` mapped only `APIError`, `UnknownApiResponseError` and `httpx.HTTPError`; `ChatService._ask` caught only `ChatProviderError`. Any other exception from the SDK (or from the cleanup in its `finally`) reached FastAPI as an unhandled 500 whose traceback can carry the SDK's message, which may echo the system prompt (the agenda context).
Decision: Both layers get a last `except Exception`. In the Gemini chat provider the client factory, the request building, the call and reading `response.text` are all inside one guarded block, and the last catch raises `ChatProviderError("Gemini request failed")` `from None`; closing the SDK client is its own step that logs a failure by class name and never raises, so it cannot replace the call's outcome (review finding, round 1). In the service it logs one warning carrying only the provider name and the exception's class name (`error_class`; no message, no `exc_info`) and raises `ChatUnavailableError("failed", "The chat provider failed: the request could not be completed")` `from None`, which the route already answers as 502. `CancelledError` and other `BaseException`s pass through, so a cancelled turn is still cancelled and releases the lock. The summary provider is not changed: it is not part of chat, and its callers have their own failure handling.
Alternative: A catch only in the service (the adapter's own text still reaches any other caller of the provider, and the adapter is the layer that knows the SDK); a catch in the route (the service would hold the lock and log nothing); logging with `exc_info` for debugging (the traceback holds the text we are hiding).
Reason: The two catches are the same rule at the two places an unknown failure can first be caught, and neither can emit the exception's text.
Where: `src/command_center/adapters/summary_gemini.py` (`GeminiChatProvider.complete`); `src/command_center/services/chat.py` (`_ask`); `tests/test_chat_provider_hardening.py`, `tests/test_chat_hardening.py`.
Revisit when: A third provider with its own SDK is added, or the log port gains a way to attach a redacted traceback.
