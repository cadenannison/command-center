# 0247. The schema guard reads every file and every reference, and accepts only literal table lists

Status: accepted. Replaces the checker of 0232 (the decision, the ledger base and the revisit condition of 0232 stand).

Context: Review of 0232's guard found ways round it: it read only files that contain the text `LedgerBase` or `CompletionRow`; it looked at calls only, so `f = md.create_all`, `from x import create_all as c`, `getattr(md, "create_all")`, `functools.partial(md.create_all, ...)` and `conn.run_sync(md.create_all)` passed; and any `tables=` counted as naming its tables, including `tables=chosen`, a variable that could hold the completions table.
Decision: `tests/test_schema_guard.py` parses every `.py` file under `src/command_center` and flags every reference, not only calls: an attribute, name or import of `create_all` or `CreateTable` (including an alias), a string constant or a sum of constants that spells one of them or `getattr(x, "create")`, and `.create(...)` on `X.__table__` or `X.tables[...]`. The one `create_all` it accepts is a direct call that either has `tables=[...]` as a non-empty list literal of `<x>.tables["name"]` (a variable, a call, a comprehension, a starred item or `None` is refused), or has no `tables=` and is called on `<Base>.metadata` for a `DeclarativeBase` subclass that the same file defines (it has a fresh metadata, so it cannot hold the ledger tables; `LedgerBase` is excluded). The key `item_completions` may appear in a `create_all` only in `storage/sqlite_completions.py`, the one place that backfills; that call now spells the key as a literal instead of through a variable. Every bypass above has a snippet test that fails if the checker stops seeing it, and a behavioural test builds the store (`create_item_ledger`) on a database that holds an old `item_ledger` and no completions table and asserts that the completions were copied, and not copied again on a second start.
Alternative: Give `CompletionRow` its own declarative base (still the better design; blocked as in 0232 by two migration fixtures that a task card has not allowed to change); list the allowed call sites by file and line (brittle); a runtime check inside `ensure_ledger_schema` (the bypass would not call it).
Reason: A guard has to fail on every way of spelling the call that it can see, and it can only see all of them if it reads every file.
Where: `tests/test_schema_guard.py`; `src/command_center/storage/sqlite_completions.py` (`ensure_completions_table`).
Revisit when: A card allows the two migration fixtures to change (0232), then drop the guard. The guard also refuses any `.create` attribute (a Table in a variable), `sorted_tables`, `to_metadata`/`tometadata`, `DDL`, `methodcaller`, any `<x>.tables` that is not indexed by a literal name, and a string that spells `CREATE TABLE`. Known limit: a table-creating name built at run time from something that is not a constant (`getattr(md, name)`) is not seen, nor is `class _Base(DeclarativeBase): metadata = LedgerBase.metadata`; review has to catch those.
