# 0378. The Events widget lists calendar events from GET /v1/events in pure helpers

Status: accepted

Context: The Events widget (kind events) shows what is on the calendar today and after. `GET /v1/events?from&to` returns every kind, one `Event` shape; it has a `link`, but no location, all-day flag or calendar name field.
Decision: Window [today's local midnight, +7 calendar days). Calendar events only (`kind` "event"); weather, tasks, assignments and email never; cancelled events and ones without a readable start are left out. Days are local calendar days built with calendar arithmetic, so a 23 or 25 hour day (DST) is one day; the clock is always a parameter. A ranged event is listed on every day it overlaps (an end exactly at midnight does not reach the next day), a point event on its own day. Groups: Today, Tomorrow, then "Mon, Nov 16"; all-day events first, then by start, ties by id. All-day is read from the times: a start at a local midnight and an end at a later local midnight (the feeds send dates). Location is `raw.location` when it is a non-empty string (iCal events); the API has no field for it. The link is the event's `link`, only http and https, new tab, `rel="noopener noreferrer"`, accessible name "Open <title> in a new tab". Tiers (width): W1 time and title; W2 adds the source dot, end time and location; W3 adds the Now chip (every event in progress) and the Next chip with a bolder title (the earliest timed event still to start). All-day events are never Now or Next. Tiers (height): H1 two rows (now and next), H2 six rows, H3 twelve rows; H1 and H2 list today and tomorrow only and hide events already over, H3 lists later days and keeps today's finished events. At H1 the rows marked Now or Next come first (an all-day event cannot push them out). Now is marked on today's row only; a multi-day event counts once per day it is listed on. Not built: the W3 day strip and the H3 free-time line of the spec (they need a scale and a working-hours rule the card did not give), and the calendar name (no API field). Rows past the limit, and later days at H1 and H2, are counted as "+N more". Times are 12-hour in the local zone. Errors show fixed text only.
Alternative: Markers at every width (the spec draws a Now chip on the row without a width rule; the card put it at W3). A new `/v1` field for location and all-day (an additive API task, not in this card). Expanding rows with notes (no notes API for events).
Reason: Everything the widget needs is already in `/v1/events`; grouping on the client honours the user's local day.
Consequences: A timed event that really runs midnight to midnight looks all-day. Calendar feeds all show the one Calendar dot. The Events widget is switched on in `dashboard-grid.tsx`; `dashboard-grid.test.tsx` and `dashboard-page.test.tsx` were changed (tests: modify) to give the grid a query client and a stubbed fetch and to assert the exact request set.
Where: `ui/src/features/dashboard/events-model.ts`, `events-widget.tsx`.
Revisit when: the API gains location, all-day or calendar-name fields, or the markers should show at every width.
