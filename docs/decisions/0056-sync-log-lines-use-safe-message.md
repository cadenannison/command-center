# 0056. Sync log lines carry adapter text only through safe_message

Status: accepted. Extends 0052 to log records; it does not replace 0052.

Context: 0052 redacted every message `SyncService` keeps in a state or returns, and named "a log line" as a place that was not covered yet. `SyncService` logged `describe(exc)` (the adapter's error text cut to 200 characters, not redacted) in the retry, give-up and failure warnings, both in the message and in the `reason` extra field. An adapter error that names an email address or an account number therefore reached the log. `describe` also cuts before it redacts, so a digit run straddling the cut would have survived as a partial number.
Decision: Every adapter-derived string in a `sync.py` log record is `safe_message(error_text(exc))` (redact, then trim to 200), in the message text and in `reason`. The retry warning computes it once and uses the same value for both. The source and attempt fields are unchanged. No exception class is added to the records, because `JsonFormatter` (decision 0051) keeps only allowlisted extra fields and would drop it. `describe` stays in `services/errors.py` for its own tests and for callers whose text is not adapter-derived; nothing in `sync.py` uses it any more.
Alternative: (a) Redact in a logging filter or in `JsonFormatter`: it covers every logger, but a plain `logging` handler (the test runner, a future desktop handler) would still see raw text, and the rule would live far from the code that knows which strings are adapter text. (b) Make `describe` redact: it is also used where the text is not adapter-derived, and the name says "short", not "safe". (c) Log the class name alone and no text: it loses the reason that the retry and give-up lines exist to give.
Reason: Same helper and same order as the state messages, so a log line and the state it describes cannot disagree about what was removed.
Where: `src/command_center/services/sync.py` (`_sync_locked`, `_fetch_with_retry`); `docs/contracts/services.md`; tests `tests/test_sync_log_redaction.py`.
Revisit when: another service logs adapter text (settings `connect`, the scheduler: both log class names only today), or `JsonFormatter` allowlists an `error_class` field so the class can be recorded as well.
