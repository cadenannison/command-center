# 0287. decisions-by-file resolves bare names from tracked files, and from untracked ones only under src, tests and docs

Status: accepted

Context: `scripts/gen_decision_index.py` turns a bare file name on a `Where:` line (`agenda.py`) into a path by looking it up among the repo's files. It listed them with `git ls-files --cached --others --exclude-standard` over `src/ tests/ docs/ scripts/ .claude/ .github/`, so an untracked scratch file in any of those folders could make a name ambiguous (and so dropped) or resolve a name that exists only on one machine. `gen:check` then passed or failed locally for a reason CI, which sees only committed files, never has.
Decision: Resolution uses two lists: every tracked file (`--cached`, so staged files count) in the six folders above, and untracked non-ignored files only under `src/`, `tests/` and `docs/` (`_NEW_FILE_FOLDERS`). A scratch file in `scripts/`, `.claude/` or `.github/` no longer changes the output. Untracked files under the three folders are kept on purpose: a record that names a module written in the same change must resolve before the human commits, or the local build would drop a line that CI's build (after the commit) adds, and `gen:check` would fail in CI instead. Outside a git checkout, or when either `git ls-files` call fails, the code walks the six folders as before.
Alternative: Tracked files only (rejected: a new file named by a new record would be missing locally and present in CI, so a clean local `gen:check` would fail after the commit). Record the limit and change nothing (the card's other option; rejected because the narrower rule costs little and closes the common case). Skip files that look like scratch by name (rejected: a guess).
Reason: The set of files the result depends on should be the set the committed tree will have, as far as that can be known before the commit.
Consequences: The limit that remains: an untracked scratch file under `src/`, `tests/` or `docs/` whose name matches a bare name on a `Where:` line still changes the local result (it can make the name ambiguous, or resolve it) and not CI's. Delete such a file or give the `Where:` line a full path. It is also listed in `docs/STATUS.md` under known quirks. Staged-but-uncommitted files count as tracked, so `git add` and commit give the same result. A bare name whose only file is untracked outside the three folders is now dropped locally, which matches CI.
Where: `scripts/gen_decision_index.py` (`_repo_files`, `_git_files`, `_NEW_FILE_FOLDERS`), `tests/test_gen_decision_index_untracked.py`, `docs/STATUS.md`.
Revisit when: A scratch file under the three folders causes a real local-versus-CI difference (then use tracked files only and have the generator warn about untracked ones), or CI builds from something other than a git checkout.
