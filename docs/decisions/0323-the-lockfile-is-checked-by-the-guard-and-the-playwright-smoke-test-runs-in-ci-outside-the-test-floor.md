# 0323. The lockfile is checked by the guard, and the Playwright smoke test runs in CI outside the test floor

Status: accepted

Context: Decision 0301 left the contents of `ui/pnpm-lock.yaml` unchecked ("a non-registry resolution passes"). Agents may not edit `scripts/ui.sh`, and `.github/workflows/ci.yml` is guarded, so the change is a patch for the human (`$TMPDIR/p1b-guard.patch`, `git apply --check` clean).
Decision:
- `bash scripts/ui.sh lockcheck [file]`, also run by `guard`, accepts a lockfile only if every package has `resolution: {integrity: sha512-<88 base64 characters>}` and nothing else; no tarball, git, directory, URL, link, workspace, `npm:` alias or portal source; and the only top-level keys are `lockfileVersion`, `settings`, `importers`, `packages` and `snapshots` (so `overrides`, `patchedDependencies`, `pnpmfileChecksum`, `catalogs` and `packageExtensionsChecksum` fail, also when indented under another key), and no line contains a backslash (pnpm never writes one; a YAML escape such as `"l\x69nk:"` would otherwise hide a source from the text match; found by the reviewer). It is line based and fails closed on any other shape. Both YAML documents in the file are checked. Tested against the real lockfile (accepted) and 16 mutated copies (all refused); the mutation script was run from the scratchpad and is not in the repo. Known gaps: a non-empty `configDependencies` under the first document is not rejected (the workspace guard bans it at the source), and a dependency literally named `npm`, `link`, `file`, `git`, `http` or `https` would fail the check (fails closed).
- `gen-check` (decision 0320) is part of `ui:check` and the CI `ui` job. mise gets `ui:gen:check`, `ui:lock:check` and `ui:e2e` (the patch); `ui:gen` is already in `mise.toml`.
- CI `ui` job: after the build, Playwright's own browser download for chromium, then `pnpm run test:e2e`. The browser comes from Playwright's CDN, not the lockfile, at the version the locked `@playwright/test` names; that download is outside the 0301 controls. `--with-deps` also installs system libraries with apt (sudo) on the runner, which is more than the browser download; drop it if the runner image already has them. The Playwright test is not in `ui/.test-floor` (0303).
Alternative: Parse the lockfile with a YAML library (rejected: a new dependency or Python in the UI gate). Leave the lockfile to human review (rejected by the card). Cache the Playwright browser by hash (not now).
Reason: Install-time code and non-registry sources are the routes the guard exists to close; the lockfile is where they would appear.
Consequences: A pnpm release that changes the lockfile shape (a new top-level key) fails the guard until the check is updated, deliberately. The rule is a text check, not a proof; the human still reads lockfile diffs.
Where: `scripts/ui.sh`, `mise.toml`, `.github/workflows/ci.yml` (the patch), `ui/playwright.config.ts`, `ui/e2e/`.
Revisit when: pnpm changes the lockfile format, or the Playwright run moves to a pinned browser image.
