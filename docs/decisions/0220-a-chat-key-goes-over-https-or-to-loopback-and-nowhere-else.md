# 0220. A chat API key goes over https, or over http to loopback only

Status: accepted. Narrows 0160 (which let a key ride http to any local host).

Context: Decision 0160 lets a chat provider be reached over plain http when its host is local (loopback, RFC1918, ULA, a single-label name, `*.local`, `*.localhost`). The OpenAI-compatible provider also attached `Authorization: Bearer <key>` to every call, so a key stored for a server on the LAN crossed the network in clear text, and a single-label or `*.local` name is whatever the local resolver (or a rogue device answering mDNS) says it is. The agenda context was already accepted as sent in clear text on a LAN (0160); the key is a credential that works elsewhere.
Decision: `core/urlcheck.py` gets `may_send_key(url)`: https is always fine (the URL must still pass `require_chat_base_url`, which raises ValueError); plain http is fine only to the exact name `localhost`, 127.0.0.0/8, `::1` and `::ffff:127.x`. Not loopback, so refused: a LAN address, a single-label name, `*.local`, and `*.localhost` (0221). NAT64 and IPv4-compatible forms are not unwrapped for this purpose (a NAT64 address is a gateway, not this machine). `OpenAICompatibleChatProvider._headers(base)` calls it only when a non-blank key is stored and raises `ChatProviderError("The chat server key is not sent over plain http to this address; use https")` before any request is built. A server that needs no key (none stored, or blank) is still called over http on the LAN, as before.
Alternative: Drop the header and send the request anyway (the agenda still goes, and the user sees an unexplained 401 from the server); put the check in `post_json` so every provider is covered (the only provider that sets a header is this one, and the card names `chat_openai.py`; revisit if a second provider sends credentials); treat `*.localhost` as loopback per RFC 6761 (decision 0221 declines to trust that name).
Reason: The refusal is loud and says what to change, and the only cleartext hop that remains for a key is one that never leaves the machine.
Where: `src/command_center/core/urlcheck.py` (`may_send_key`); `src/command_center/adapters/chat_openai.py` (`_headers`); `tests/test_urlcheck_key_transport.py`, `tests/test_chat_provider_hardening.py`; `tests/test_chat_adapters.py` fixtures (0224).
Revisit when: A second provider attaches credentials (move the check into `chat_http.post_json`), or a provider that must use a LAN http server with a key has a real use.
