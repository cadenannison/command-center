# 0052. Connect validates the merged credentials; service messages are redacted

Status: accepted. Supersedes the "validate receives exactly the submitted credentials" part of 0020.

Context: A user who changes only `base_url` must not have to retype the token. 0020 already kept unmentioned stored keys, but validated only the submitted keys, so an adapter that needs both (Canvas checks the token against the base URL) rejected a partial update or validated against nothing. Separately, a sync state's message carries the adapter's error text, and `GET /v1/settings` returns it; an error can name an address or an account number.
Decision: `SettingsService.connect` reads the stored credentials, overlays the submitted fields whose value has non-whitespace content, and gives the merged set to `validate`. It writes only the keys whose final value differs from the stored one (the keychain is touched less). A blank or whitespace-only value always means "keep"; clearing a field is disconnect then reconnect. If the stored credentials cannot be read, connect returns `ok=false` with `secret store unavailable` and validates nothing. `SyncService` passes every message kept in a state through `core.redact.redact`, then `trim(…, 200)`, in the two places a state is built (`_remember`, `error_state`); redact runs first so a cut cannot split a number. `ConnectResult.message` gets the same helper (`services.errors.safe_message`) wherever it carries adapter text: an accepted or rejected `ValidationResult.message` and `Could not validate credentials: …`. This was added at the project manager's request, because validate text can carry an email address too. The fixed messages need no cleaning.
Alternative: validate only the submitted keys (0020), which cannot check a partial update; let a blank value clear the key, which makes an empty form field destructive and the web form already treats blank as keep; redact in the api layer, which would leave the in-memory state and the web page unprotected; redact only the adapter text, which leaves the prefix and the fixed messages to drift.
Reason: The merged set is what the sync will use, so it is what must be valid. Redacting where the state is built covers every reader (api, web, workers) at one point.
Where: `src/command_center/services/settings.py` (`connect`); `src/command_center/services/sync.py`; `src/command_center/services/errors.py` (`safe_message`); `docs/contracts/services.md`; `docs/contracts/api.md`; tests `tests/test_settings_merge.py`, `tests/test_sync_message_redaction.py`, `tests/test_connect_message_redaction.py`.
Revisit when: A source needs to clear one field without losing the rest (an explicit per-key delete), or a message that is not redacted today (a log line, an exception text a route returns) reaches a screen or a client.
