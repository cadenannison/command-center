# 0122. A source completion is stamped on the first sync that sees it; a vanished item is removed, not done

Status: accepted

Context: Canvas and similar sources report an item done by changing its status, and drop old items from the feed without saying why. A history that called every disappearance a completion would be wrong, and one that missed a completion because the item arrived already done would lose it.
Decision: In `record_sync`, an item whose incoming status is `done` gets `done_by = "source"` and `done_at` = the sync's time on the first sync that sees it done, including an item that first arrives done; later syncs keep that first time. An item stored in the window and not returned is marked gone (`gone_at`), unless it is already done at the source or by the user, or it was stored done before the ledger saw it (leaving the feed is what finishing does). Weather is exempt (a forecast replaced daily is not an item that disappeared). A gone item that comes back is no longer gone. A user check-off keeps its own time and wins over a later source completion; undoing a user check-off does nothing when the source says done. A failed fetch writes nothing, so it cannot mark anything removed. Items outside the sync window are not in `prior` and are never marked. An item whose date moves beyond the end of the window (a rescheduled item) is stored and not returned, so it is listed as removed until a later window returns it, which clears it. An item the source reports open again after a completion loses that completion (decision 0129).
Alternative: Treat every disappearance as done (wrong for deleted and rescheduled items); stamp a source completion with the item's due date or the source's own timestamp (most feeds have none and the field is unreliable).
Reason: The first sync that observes the fact is the earliest honest time we have. Keeping it stable means the history does not move when the next sync repeats the same status.
Where: `src/command_center/storage/sqlite_ledger.py` (`record_sync`, `_mark_gone`, `_mark_done_by_source`, `_clear_reappeared`), `sqlite_items.py` (`check_off`, `undo`); tests in `tests/test_ledger_sync.py`.
Revisit when: A source exposes a trustworthy completion time; the adapter can then supply it and `record_sync` can prefer it.
