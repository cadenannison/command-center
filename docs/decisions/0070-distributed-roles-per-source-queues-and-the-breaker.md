# 0070. Distributed roles, one queue per source, and where the breaker sits

Status: accepted; its known gaps (the api reading in-memory state, connect syncing in the api, disconnect not purging shared state) are closed by 0074

Context: Task 3b. Decision 0047 gave `JobQueue` one lane per key prefix and at-least-once delivery. The card wants one worker container per source, a scheduler that publishes sync jobs, and a `CircuitBreaker` (0048) in the worker loop. `Job` carries no payload (0047), so a worker cannot be told which source it serves from the job alone.
Decisions:
1. **Roles.** `python -m command_center.workers` takes exactly one of `--source NAME`, `--normalizer`, `--scheduler`, and an optional `--heartbeat-file PATH` (touched every 15 s, used by the container healthcheck). Every role needs `CC_REDIS_URL`; without it the process exits with a message naming the variable.
2. **One queue per source.** A source's jobs live under the key prefix `cc-<source>`. A worker consumes only its own prefix, so a source that is down, slow or poisoned cannot hold up another. The scheduler's `SyncEnqueuer` holds a `Mapping[str, JobQueue]` with one queue per connected source. The `JobQueue` port did not change for this. A `Job` with a source other than the queue's is dead-lettered as `WrongJob` rather than fetched.
3. **Breaker in the worker loop.** Each worker holds one `CircuitBreaker` state for its source: 5 consecutive Transient failures open it, 5 minutes cool-down, then one half-open trial. While it is open the worker does not consume at all, so jobs stay on the queue untouched and no attempt is spent. `AuthExpired` and `FatalError` do not count as failures; they count as an answer, so they close the breaker (record a success), which also ends a half-open trial. A missing credential or an adapter bug neither counts nor closes it (the source was not reached), so a half-open trial stays open until a job gets an answer. Any other exception from `fetch` is retried but does not count either, so a bug cannot open the breaker and hide itself as "source down".
4. **Outcomes.** Transient: log class, `queue.fail` (RetryPolicy, 0047), and on the last attempt an error report. Fatal: error report and `queue.dead_letter`. AuthExpired or no credentials: a `reconnect` report and ack, no retry. Success: an `ok` report with the events, then ack. Reports go out before the ack, so a crash between them only re-delivers the job; the normalizer is idempotent (0028, 0071).
5. **Stale reports.** The normalizer drops (acks) a report older than the stored state for its source, so a redelivered old report cannot overwrite a newer result.
6. **Single-process mode is unchanged.** `CC_MODE=single` (the default) builds the same container as before; `CC_MODE=distributed` needs `CC_REDIS_URL`, and the api then does not start the in-process scheduler.
7. **One existing test changed, with the project manager's permission** (`.claude/allow-test-edits`): `tests/test_smoke.py::test_unbuilt_composition_roots_fail_loudly` asserted that `workers.__main__.main()` raises `NotImplementedError("not built yet")`, which cannot hold once the entry point exists. It is now `test_the_worker_root_imports_without_running`: it imports the module and checks `main` is callable, never calling it, the same shape as the existing `desktop.main` case. Alternative: call `main()` with patched argv and settings; rejected because it would start a consumer loop.
Alternative: (a) One shared queue with a worker per source that skips foreign jobs: wastes deliveries and breaks the retry count. (b) Add a `source` argument to `JobQueue.consume`: changes a port every adapter implements, for something a key prefix does. (c) Count every exception toward the breaker: a code bug would then look like an outage. (d) Keep consuming while open and fail jobs fast: burns the attempts of every job during an outage, so they dead-letter when the source comes back.
Reason: isolation per source is the point of one container per source; leaving jobs queued while the breaker is open means an outage costs time, not data.
Where: `workers/__main__.py`, `workers/sync_worker.py`, `workers/normalizer.py`, `services/scheduler.py` (`SyncEnqueuer`), `config.py` (`mode`, `redis_url`); tests `test_sync_worker.py`, `test_normalizer.py`, `test_sync_enqueuer.py`, `test_workers_main.py`, `test_chaos_distributed.py`.
Not changed (found in review, accepted for now): (a) the scheduler publishes a job every round even when earlier jobs for that source are still queued, so a long outage leaves a backlog of identical jobs that run one after another on recovery; the port has no queue-depth call to collapse them. (b) The heartbeat file proves the process's event loop is alive, not that passes succeed; a role whose every pass raises stays healthy until the process exits. Touching the heartbeat only after a pass that did not raise is the fix. (c) `adapters/source_registry.py` and `adapters/secret_backend.py` build concrete adapters outside the three roots named in AGENTS.md rule 2; they are plain factories called only from those roots, accepted here as the way to share the list of sources between the api and every worker.
Known gap: the api process still answers `GET /v1/sources` and the settings page from its own in-memory `SyncService` state, so in distributed mode it does not yet show what the normalizer recorded in the shared store (0071). Connecting a source still runs one in-process sync in the api. Disconnecting does not purge shared sync state or reports already in flight.
Revisit when: the api reads sync state through `SyncStateStore`; a source needs a different breaker threshold; a job needs a payload (then per-source queues may collapse into one).
