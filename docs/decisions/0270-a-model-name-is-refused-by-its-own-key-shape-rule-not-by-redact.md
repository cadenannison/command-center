# 0270. A model name is refused by its own key-shape rule, not by redact

Status: accepted; supersedes in part 0258 (the model-name test; the address rules of 0258 stand); superseded in part by 0290 (more prefixes, `@`, hex, `user:password`, and the limit of 200)

Context: Decision 0258 refused a model name when `redact` changed it, so a real hosted name such as `meta-llama/Llama-3.3-70B-Instruct-Turbo-Free` was refused: `redact` masks a 32-character token, and that name holds a 32-character run of letters, digits and dashes. A user of a hosted OpenAI-compatible server has no workaround (an Ollama user can `ollama cp` to a short name). 0258's own "Revisit when" named this case. Model names are made of short words joined by `-`, `.`, `_`, `:` and `/`; a key is one long unbroken run or carries a vendor prefix.
Decision: `core.chat.model_name_looks_like_api_key(name)` is true when the stripped name (1) starts with a known key prefix: `sk-`, `AIza`, `ghp_`, `gho_`, `ghu_`, `ghs_`, `github_pat_`, `AKIA`, or `xox` plus one of `b a p r s` and `-`; or (2) holds one run of 32 or more `[A-Za-z0-9]` characters (any other character ends a run, so the separators `- . _ : /` and also `@` and `+` break it); or (3) is longer than 100 characters. It does not call `redact`, so the number-run, address and URL rules no longer apply to a model name. `services/chat_settings.normalise_provider` and the card's `_shown_model` use it in place of `looks_like_api_key`. The 100-character check in the service still runs first with its own text ("at most 100 characters"); other refusals keep the fixed text "looks like an API key; keys go on the key card". A refused value is never echoed, stored or shown again (unchanged). A key-shaped model already stored is still an unusable provider setting (`ChatNotConfiguredError`). `looks_like_api_key` and `address_holds_api_key` are unchanged: an address path segment is still tested by `redact` and the three prefixes (0258).
Alternative: Allow any name that matches the model pattern and holds a `/` or `:` (0258's own suggestion; rejected: a key pasted after a `/` or `:` would pass, and `llama3.1:8b-instruct-q4_K_M` has no need of it). An allow-list of known model names (rejected: it would be out of date within weeks and would refuse every new or self-hosted model). Loosen the token rule in `redact` (rejected: `redact` protects text sent to a provider, where a false negative leaks data; a model name is a settings field and the cost of a miss differs; the card forbids touching it).
Reason: A key has no separators inside its random part, so one unbroken alphanumeric run of 32 or more is the best signal that does not also fire on ordinary names; the prefixes catch short keys of the common vendors. A false refusal still costs the user a rename, but now only for a name that really has a 32-character word.
Consequences: Real hosted names of any length up to 100 are accepted. A key of 31 or fewer alphanumeric characters per run with no listed prefix passes, and so does a key whose runs are split by `-` or `_` (`gsk_` and `xai-` keys of 32 or more characters are still caught by the run rule). The card's text still says keys go on the key card. A name of 32 or more letters and digits with no separator, such as a long hash, is refused.
Where: `src/command_center/core/chat.py` (`model_name_looks_like_api_key`), `services/chat_settings.py` (`normalise_provider`), `web/ai_settings.py` (`_shown_model`); `tests/test_chat_key_shapes.py`.
Revisit when: A key of another vendor is pasted into the model field and stored, or a real model name with a 32-character word is refused.
