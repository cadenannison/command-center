# 0387. The Needs me widget keeps the server's order and reads its one time from `at`

Status: accepted

Context: `GET /v1/needs-me` (0385, 0386) returns up to 20 ranked rows across tasks, assignments, email and events, each with one time `at` (due, else start) and no end time. The widget is the only cross-kind widget. Row ids and kinds are as the server sends them.
Decision: The widget shows the rows in the server's order and never re-sorts, filters by priority or caps them itself; the only thing it drops is a row of kind weather (it has no kind label). Time labels come from `at` and the clock parameter alone (`needs-me-model.ts`): an event whose `at` is not after now is "Now" (the server lists an event only while it is in progress or ahead, 0385, so no end time is needed), an event ahead is "Starts 2:30 PM", anything else is "Overdue" once `at` is before now and "Due 5:00 PM" otherwise (due exactly now is not yet overdue, as in the Tasks groups, 0373). A row on another local day gets "Tomorrow", a weekday within the next week, or "Nov 20" before the time ("Starts Tomorrow 9:00 AM"); days are local calendar days from Date arithmetic, so a 23 or 25 hour DST day is one day (0378). Kind labels: Task, Assignment, Reply (email), Event. Width tier 1 shows the count ("4 need you") and the top item only, with no "+N more" because the count says it; tier 2 adds the source dot and a ranked list; tier 3 adds the top reason sentence. Height tiers cut the list to 3, 6 or all rows with "+N more" (as Tasks, spec Size rules). Each row has the Tasks reasons disclosure (aria-expanded, every reason with its points as text) and the Tasks link rule (http and https only, new tab, noopener noreferrer, title in the name). Query: key `["needs-me"]`, staleTime 30 s, refetch on focus, keepPreviousData; the state rules are `deriveQueryState`; the error text is fixed and the empty state is "Nothing needs you right now".
Alternative: Re-sort by time or priority in the client (rejected: the server's order is the ranking and the one place it is tested). Ask for events' end times to show "Now" exactly (rejected: the route is additive and read-only, and the server already excludes an event that has ended; the label can lag by at most one refetch). Show "+N more" at W1 as well (rejected: it repeats the count).
Reason: One ranking, one definition of urgency, no second source of truth for what "needs me" means; pure helpers keep the day, DST and overdue rules testable with `now` as a parameter.
Where: `ui/src/features/dashboard/needs-me-model.ts`, `use-needs-me.ts`, `needs-me-widget.tsx`, wired in `dashboard-grid.tsx`; tests `needs-me-model.test.ts`, `needs-me-widget.test.tsx`, `ui/e2e/dashboard-needs-me.spec.ts`.
Revisit when: the dismiss card lands, an end time is added to the row, or the server starts sending weather (it does not).
