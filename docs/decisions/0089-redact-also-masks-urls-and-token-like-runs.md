# 0089. `redact` also masks http(s) URLs and token-like runs

Status: accepted; extends 0011

Context: Task 4d, closing the "Not done" of 0085. `redact` removed email addresses and digit runs of six or more and nothing else, so a feed URL (an iCal link carries a secret in its path or query) or an API-token-shaped string in a title or a worker's message reached the summary provider and the stored sync message untouched. Credentials stayed out of messages because no code path put them there, not because `redact` would have found them.
Decision: two rules added to `core/redact.py`, run in this order: (1) `http://` or `https://` (scheme case-insensitive) followed by non-whitespace becomes `[url]`; (2) emails as before; (3) a maximal run of 24 or more characters from `A-Za-z0-9_-` that contains at least one ASCII digit becomes `[token]`; (4) digit groups as before. URLs go first because they may hold `@`, digits and query tokens, and a trailing `.` or `)` is swallowed with the URL (over-redaction, as before). Emails go before tokens so an address is masked in one step. A run with no digit (an ordinary long word, a hyphenated phrase) is untouched, and so is anything shorter than 24 characters, including an ISO date. The token regex is anchored by a lookbehind so each character is read once; matching stays linear (13 adversarial timing cases in the new test file). `redact` stays idempotent: `[url]` and `[token]` contain nothing the rules match.
No narrowing was needed: every existing test in `tests/test_redact.py` and elsewhere passes unchanged.
Tests: `tests/test_redact_urls_and_tokens.py` (new). Hypothesis properties: ordinary words and standalone ISO dates are untouched; a `fake-` token of 24 or more characters never survives; a feed URL, its host and its query value never survive; `redact` is idempotent on URL- and token-shaped text. Examples: `user@host` and `user:pw@host` URLs, trailing `.`, `HTTPS` and `HtTp`, 23 characters kept and 24 masked, 24 without a digit kept.
Alternative: (a) Only URLs: leaves a pasted token. (b) A shorter threshold (16 or 20): masks long ordinary identifiers and dates with slugs more often, and 24 is the card's number. (c) Mask any long run, digit or not: destroys long words and German compounds for no gain, since a secret from a generator nearly always has a digit. (d) Mask by entropy: needs a threshold nobody can explain, and it would change with the alphabet.
Reason: a false positive costs a word of context; a miss leaks a credential, so the rule leans to over-redaction but stays out of ordinary prose.
Not masked (by design): a secret shorter than 24 characters or without a digit, such as `fake-token-12345678` (19 characters; its digit run is still masked as `[number]`) or `fake-secret-abc123`. Also not masked: tokens whose characters fall outside `A-Za-z0-9_-` are cut into separate runs (standard base64 with `+`, `/`, `=`; dot-separated tokens such as JWTs), and any piece under 24 characters or without a digit survives; a scheme-less URL (`www.example.com/feed?token=...`) is masked only if its token is itself a 24+ character run with a digit. Credentials stay out of messages because no code path puts them in; `redact` is the second line, not the first.
Where: `src/command_center/core/redact.py`; `docs/contracts/core.md` (Redaction); `tests/test_redact_urls_and_tokens.py`.
Revisit when: a provider or a feed produces secrets shorter than 24 characters, or the false positives (a long slug with a digit in a title) show up in real summaries.
