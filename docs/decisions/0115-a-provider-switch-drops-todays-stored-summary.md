# 0115. A provider switch drops today's stored summary

Status: accepted

Context: One `summaries` table is shared by every provider, and `SummaryService` labels a stored summary with the provider that is current when it is read (`provider=self._provider.name, cached=True`). After a switch from Gemini to Ollama, `GET /v1/summary` (which the mobile repo reads) and the card would show a summary Gemini wrote under Ollama's name. The A2 web path hid this with `refresh=changed` on the card only.
Decision: (1) `SummaryStore` gains `delete(day, *, user_id="local")` (a day with no row is not an error). (2) `SummaryControl.set_provider` compares the new name with the current effective provider; when it differs, and a `forget_today` callable was given, it runs it after storing the choice. The composition root passes `lambda: summary_store.delete(agenda.today())`. (3) Choosing the provider already in use keeps the stored summary. Other days are left alone: they are history, and a past day is not regenerated. (4) The model setting (`summary_model`) is an environment value only; there is no UI to change it, so it has no switch to hook. A restart with a changed environment provider or model is not covered. (5) `refresh=changed` stays on the card path as a second guard for a container built without `forget_today`.
Alternative: (a) Store the provider name with each summary: exact for every day and restart, but a new column and a change to the `/v1` response contract the mobile repo reads. (b) Clear every stored summary on a switch: loses history that `latest_before` uses as the fallback (decision 0040). (c) Do the delete in the web route: the route would own a rule about stored data, and the API has no such route.
Reason: The mislabel only arises at a switch, today's row is the only one anyone reads, and one port method fixes it for the card and for `/v1/summary` without a schema change.
Where: `core/ports.py` (`SummaryStore.delete`), `storage/sqlite_summary.py`, `services/summary_control.py`, `app.py`; `tests/test_summary_store_delete.py`, `tests/test_summary_nonblocking.py`.
Revisit when: the model becomes a stored setting (add the same hook), a past day can be regenerated from the UI, or the label should be exact for old days (store the provider name with the row).
