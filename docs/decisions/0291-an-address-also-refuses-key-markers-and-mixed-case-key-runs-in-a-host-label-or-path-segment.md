# 0291. An address also refuses key markers and mixed-case key runs in a host label or path segment

Status: accepted; extends 0258 (the address rules of 0258 stand and are added to)

Context: Review of 0258 found these addresses accepted and stored: `.../v1;key=abc123def`, `.../v1/token=abc12345`, `.../v1/a1B2c3D4e5F6g7H8i9J0`, `https://a1B2c3D4e5F6g7H8i9J0.example.com/v1` and `.../v1/ASIAIOSFODNN7EXAMPLE`. `redact` did not change them: each is shorter than its 24 or 32 character token rules.
Decision: `core.chat.address_holds_api_key(address)` is also true when (1) the address, as typed or percent-decoded, contains `;`, `key=`, `token=` or `bearer` in any case; (2) a host label or a path segment (as typed and decoded) is a run of 20 or more letters and digits that holds an upper case letter, a lower case letter and a digit; (3) a path segment starts with a key prefix of the model-name list (0290) or `xox[baprs]-`. Host labels are read from the netloc as typed, because `urlsplit().hostname` lowercases and would hide the case mix, and are tested both as typed and percent-decoded, like a path segment (found in review); the existing `redact` test of each label (0258) stays and still skips an IP literal. A host is not tested for prefixes, so `sk-llm-gateway.example.com` stays valid (0258). A refused address is never echoed, stored or shown again (unchanged); `web/ai_settings._shown_address` uses the same function. Real endpoints stay accepted: `openrouter.ai/api/v1`, `api.groq.com/openai/v1`, `api.together.xyz/v1`, `localhost:11434`, `localhost:1234/v1`, `https://x.openai.azure.com/openai/deployments/gpt-4o` and a LAN IP with a port; `tests/test_chat_key_shapes.py` lists each as an accepted row.
Alternative: Test only lower-cased text (rejected: hides the case mix that tells a key from a long word). Refuse any 20-character alphanumeric run (rejected: long words such as `deployments` would grow into false refusals; the mix of three classes is what a random key shows). Add the marker test to the host only (rejected: the keys were in paths and in a `;` parameter).
Reason: A key is random, so it mixes classes; a word does not. The markers name the usual ways a key is attached to a URL.
Consequences: A path segment or host label of 20 or more characters that mixes upper case, lower case and a digit by chance is refused (a long identifier in a real endpoint, such as a mixed-case deployment id, would be). The user has no workaround except a shorter alias. A key made of one class, shorter than the 24 or 32 character rules of `redact`, still passes.
Where: `src/command_center/core/chat.py` (`address_holds_api_key`, `_is_mixed_key_run`, `_has_key_prefix`, `_raw_host`), `services/chat_settings.py` (`_checked_address`), `web/ai_settings.py` (`_shown_address`); `tests/test_chat_key_shapes.py`.
Revisit when: A real endpoint with a long mixed-case segment or label is refused, or a key in an address is stored.
