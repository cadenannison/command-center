# 0240. Redaction is best-effort, NFKC-normalised first, with a fixed rule order

Status: accepted; supersedes in part 0011 and 0089 (the rule list and its order); superseded in part by 0255 (the IPv4 rule moves after the digit-group rule)

Context: A review found text that `redact` let through: 4-5 digit codes, scheme-less URLs, short or digit-free provider keys, JWTs and tokens split by "." or "/", phone numbers split by other separators, comma-grouped runs, IP addresses, fullwidth "＠" and "bob [at] example [dot] com". Decision 0011 set the scope (emails, digit groups, before trim); this record sets the rule set that replaces its list.
Decision: (1) Redaction is documented as best-effort defence in depth: it masks the listed shapes and will miss a shape nobody listed, so callers still choose what text goes in (rule 6: titles, due dates and trimmed subjects only). (2) `redact` first removes invisible characters (the Unicode Default_Ignorable_Code_Point set: soft hyphen, U+034F, U+061C, Hangul and Khmer fillers, Mongolian free variation selectors, zero-width and bidi marks, word joiner and isolates, U+3164, variation selectors U+FE00-FE0F, BOM, U+FFA0, shorthand and musical format characters, tag characters and variation selectors U+E0000-E0FFF) with one character-class substitution, then NFKC-normalises, and returns the NORMALISED text. It  The original spelling never goes onward. This is what makes fullwidth "＠", fullwidth digits and no-break spaces match the plain rules. (3) Rule order: scheme URLs, scheme-less URLs, emails, spelled-out emails, key prefixes and JWTs, token runs, IPv4 and IPv6, digit groups, keyword codes. Markers: `[url]`, `[email]`, `[token]`, `[ip]` (new), `[number]`. (4) A scheme-less URL is `www.` plus a host, or a dotted host with an alphabetic TLD (2-24 letters) followed by `/`, `?` or `#`; it is masked to the next whitespace like a scheme URL. It may follow `:` or `-` (`Reset link:example.com/x`, `--example.com/x`) but not a letter, `@`, `.` or `/`. A bare `example.com` with no path is not masked (file names, `Node.js` and sentence ends without a space would be).
Alternative: Mask only the original text and keep the original spelling around the masks (rejected: the normalised form is what the matchers saw, so mapping offsets back adds code and a second spelling that could carry a lookalike). Mask a bare `example.com` too (rejected: too many false positives for no path to leak).
Reason: A review-driven list will always be incomplete, so the contract says so instead of promising more than the code does. NFKC first is the one change that fixes a whole class (lookalike characters) at once.
Consequences: Stripping invisible characters is lossy: the zero-width joiner and the variation selector inside an emoji sequence are dropped, so a joined emoji renders as its parts. It is done first because "801<ZWSP>555<ZWSP>1234" and a soft-hyphen-split key otherwise hide from every rule. Text sent onward can differ from the input in more than the masks (`ﬁ` becomes `fi`, `①` becomes `1`, a no-break space becomes a space). Idempotent because NFKC is. Worst case for time: one character, U+FDFA, normalises to 18 characters, so 200k of it becomes 3.6M characters and `redact` takes about 0.7 s on this machine, above the 0.5 s bound that holds for every other adversarial input tested (the test uses U+FB03, 3x). Matching stays linear in the normalised length. A bare `a.b/c`-style false positive: `end.Next/section` (a missing space after a period) is masked as a URL.
Where: `src/command_center/core/redact.py` (`redact`, `_BARE_URL`), `tests/test_redact_gaps.py`, `docs/contracts/core.md` (Redaction).
Revisit when: A caller needs the original text next to the redacted one, or input of unbounded size reaches `redact` (then cap the normalised length, or reject, before matching), or another leak class turns up.
