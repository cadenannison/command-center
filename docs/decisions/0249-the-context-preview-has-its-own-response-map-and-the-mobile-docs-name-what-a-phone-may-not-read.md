# 0249. The context preview has its own response map, and the mobile docs name what a phone may not read

Status: accepted. Corrects the docs of 0060, 0165 and 0182 and the OpenAPI of 0169.

Context: `docs/mobile.md` and `docs/mobile-api-notes.md` said a paired phone may call "every GET", while `api/policy.py` refuses `GET /v1/geocode` and `GET /v1/chat/context-preview` (0165, 0182). `mobile-api-notes.md` also said all chat routes answer 404 while chat is off, but 0169 and `docs/contracts/api.md` say the preview works then and returns `enabled: false`; and its error table lacked 409, 429 and 502. `GET /v1/chat/context-preview` shared the chat POST's response map, so `openapi.json`, which a separate mobile repo reads, listed 429 and 502 for a route that calls no provider and cannot return them, and described its 404 as "Chat is off".
Decision: The docs now say "every GET except two" and list both refused reads, with `/v1/geocode` in the refused list. Chat is off: `POST /v1/chat` is 404, the preview answers `enabled: false`, `DELETE` works. The error table gained 409 (chat provider setting unusable on the POST and the preview; a non-local item on `PATCH`/`DELETE /v1/items/{id}`), 429 (pairing locked; the local chat and city-search limits; a provider's own 429 is a 502, 0171) and 502 (chat provider failed; Open-Meteo failed), each with its routes, and a note that a paired phone gets the 403 first on every route in those rows except the pairing 429. The preview has its own map in `chat_routes.py`: 404 "Chat is not wired into this server" and 409, nothing else (no 422: it takes no input). That 404 is what `_service` raises when the container has no chat service, which the real app never does; the schema keeps it because the code can. Generated files were rebuilt with `mise run gen:build`.
Alternative: Keep the shared map (the schema promises errors the route cannot give, and a client generated from it handles them for nothing); drop the 404 from the preview (the code can still return it).
Reason: The schema is the contract for the mobile repo, and the policy decides what a phone may call, so neither may overstate.
Where: `src/command_center/api/chat_routes.py` (`_PREVIEW_RESPONSES`); `docs/mobile.md`; `docs/mobile-api-notes.md`; `docs/generated/openapi.json`.
Revisit when: The preview can fail for another reason, or a phone is allowed to read it.
