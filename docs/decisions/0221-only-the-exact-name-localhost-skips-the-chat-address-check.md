# 0221. Only the exact name `localhost` skips the chat address check

Status: accepted. Partly supersedes 0160 (which skipped the lookup for `*.localhost` too).

Context: `adapters/chat_http.checked_base_url` resolved every local name and public-looking name, and skipped both for `localhost` and for anything ending in `.localhost`. RFC 6761 says a resolver should send `*.localhost` to loopback, but nothing makes a system resolver or a network's DNS do so: `evil.localhost` can be an A record for 169.254.169.254 or a public address, and the old code would then call it.
Decision: Only the exact name `localhost` (case ignored) skips the check; `localhost.` with a trailing dot is a different, fully qualified DNS name that a resolver may send upstream instead of to the hosts file, so it is resolved and checked like `*.localhost` (looked up as written, dot included, because that is the name the connection resolves), and it is not loopback for the key (0220; also `127.0.0.1.`). Any other `*.localhost` name is a local name: it is resolved and refused when any address would be refused as a literal (link-local, metadata, unspecified, multicast, or public over http), and refused when it does not resolve. Loopback and private addresses are accepted for it, like `*.local`. `core/urlcheck.py` still accepts `*.localhost` as a local host for http (its tests are unchanged): core does no DNS, so the adapter is where the answer is checked. The key is never sent to it over http (0220).
Alternative: Require `*.localhost` to resolve to loopback only (stricter, but then a `*.localhost` that maps to the LAN, which `*.local` may, behaves differently for no stated reason); refuse `*.localhost` outright (breaks a user who runs a server at `llm.localhost` behind a local proxy).
Reason: A name is trusted only when it is the one name every system maps to this machine; any other name gets the same lookup check as the rest.
Where: `src/command_center/adapters/chat_http.py` (`checked_base_url`, `_is_local_name`); `src/command_center/core/urlcheck.py` (`may_send_key`, no trailing-dot stripping); `tests/test_chat_provider_hardening.py`.
Revisit when: Core gains a resolver port, so the guard can check a resolved address itself and the DNS-rebinding gap named in 0160 closes.
