# 0261. A marker never starts a new match, and a digits-and-separators run is left to the digit rule

Status: accepted; supersedes in part 0241 (token runs made only of digits and separators) and 0244 (the characters around an IPv6 run)

Context: Round 3 of R1 ran every `redact` property test with 30000 examples instead of the default 100, as the project manager asked, and found four counterexamples. (1) `0 0 0.0.0.0` was `x 0 0 [ip] y`: fixed by decision 0255. (2) `0 0 0 0-00-000-000-000-000-000` came back `x 0 0 0 [token] y`: its 24+ character tail of digits and "-" is a token run, so the token marker took part of a digit group and left the digits next to it showing. (3) `02026-11-09www.code ` and `a::000000` and `10.0.0.1a::` were not stable: the first pass put a marker next to text, and on the second pass a rule that was blocked by the neighbouring character before the marker now saw "]" and matched (`[number]www.code` became `[number][url]`; `a::[number]` became `[ip][number]`).
Decision: (1) A token run whose characters are all digits, "_", ".", "/", "+", "=" and "-" is not a token: it is left to the digit-group rule, which masks the whole group, neighbours included. (2) A scheme-less URL and an IPv6 run do not start right after one of the five markers (a fixed-width negative lookbehind per marker, not after any "]", so `[EXTERNAL]www.bank.com/reset?t=ab12cd` and `[eth0]fe80::1` are still masked), and an IPv6 run followed by a marker is a word, not an address. The key-prefix rule runs a second time after the IPv4 sweep, because a key glued after digits (`call 801 555 1AKIAIOSFODNN7EXAMPLE`) is blocked by the digit until the digit rule turns it into a marker. These are the places found where a marker unblocks a rule on a second pass; the 30000-example property runs found no other. (3) The property `test_redact_replaces_any_separator_joined_number_of_six_or_more_digits` in `tests/test_redact.py` changed, because it asserted something decisions 0244 and 0255 had already made untrue: a dotted quad is an address. Under six digits its expected text has each dotted quad replaced by `[ip]`; a group of six or more digits that is exactly a dotted quad is `[ip]`; every other group of six or more is `[number]`. Its generator and the six-digit floor are unchanged.
Alternative: Judge idempotence by running the whole pipeline twice and returning the second result (rejected: it hides which rule is wrong and doubles the cost). Forbid "[" and "]" in input (rejected: titles contain brackets). Block the URL and IPv6 rules after any "]" (adopted first, then rejected by the review: a subject tag such as `[EXTERNAL]` hid `www.bank.com/reset?t=ab12cd`). Keep `[token]` for digit-only runs (rejected: it leaves part of a phone-like number readable).
Reason: Over-redaction is the stance (0011) but a partial mask is the worst outcome: it shows part of a number and claims it is masked.
Consequences: A run of 24+ characters made only of those symbols and fewer than six digits (a long run of dashes with one digit) is no longer a token and stays; it carries no secret. Known gap: another rule that starts after a marker and was blocked by the digit before it may behave the same way; add its marker lookbehind or a second pass when one is found. `redact` stays idempotent on 30000 examples of every property in the three redact test files, run twice (the other properties found nothing). Known limitation: input that literally contains one of the five markers immediately before a URL leaves that URL unmasked (`[number]www.example.com`), because `redact` must be idempotent and a marker typed in the input cannot be told apart from one the first pass emitted. Severity: low, since only text the author controls is affected. Follow-up option: let `_BARE_URL` start after a digit run, so the first pass matches the second and no marker exemption is needed; the cost is some over-redaction.
Where: `src/command_center/core/redact.py` (`_redact_run`, `_DIGITS_AND_SEPARATORS`, `_NOT_AFTER_MARKER`, `_BARE_URL`, `_IPV6_RUN`, `_redact_ipv6`, the second `_KEY` pass in `redact`), `tests/test_redact.py` (the property above), `tests/test_redact_gaps.py`.
Revisit when: A new rule outputs a marker next to text a blocked rule would then accept; add that marker to the rule's lookbehind.
