# 0384. Export is the stored v1 document, and undo and redo shortcuts wait for a shortcuts setting

Status: accepted

Context: Card E1 asks for an Export button that downloads the layout and for Ctrl or Cmd Z shortcuts in edit mode, off by default if the codebase has a shortcuts setting.
Decision:
- Export: `edit-model.exportDocument(name, layout)` returns the file name and content; `download.downloadText` saves it through a Blob and a temporary link, with no network call (nothing for the strict CSP, 0301, to block). The content is `layoutToWire(history.present)` as JSON with two-space indentation and a final newline: exactly the document the save path sends (keys `version` and `items`), so it is the stored v1 format and carries no dashboard name, revision or time. It is what is on screen, including a change not yet saved.
- File name: `command-center-<dashboard name>-layout.json`. Letters (any script), digits, dot, underscore and hyphen are kept; every other run of characters becomes one hyphen; leading and trailing hyphens and dots are trimmed; the name is cut at 60 characters; an empty result becomes `dashboard`. Case is kept ("Main" gives `command-center-Main-layout.json`). A name such as `../etc/passwd` therefore cannot make a path.
- Shortcuts: the codebase has no shortcuts setting (a search of `ui/src` finds none, and `/v1` has no such key). The card says to build only the toolbar buttons in that case, so Ctrl or Cmd Z and Shift variants are not built. Follow-up: when a shortcuts setting exists (a display setting in /v1, default off), add a keydown handler active only in edit mode that skips events from `input`, `textarea`, `select` and `contenteditable`, ignores a held pick-up (the grid's own Escape and Enter keys), and calls the same `onUndo` and `onRedo` the buttons use.
Alternative: Export the sanitized layout with a wrapper holding the name and export time (rejected: the card says nothing else goes in the file, and an import later would then need to unwrap it). Install shortcuts always on (rejected: Ctrl Z in a text field or a screen reader's own keys must not be taken; the card says off by default). Keep the case-folded name (rejected: the card names the dashboard name; folding changes it for no safety gain).
Reason: What Export writes is what a future import, or the server, would read back unchanged; and a shortcut is a setting-level decision, not a UI detail.
Consequences: `layoutToWire` drops string-valued options (the wire schema allows only numbers and booleans), so they are absent from the file as they are from what the server stores today. Two dashboards with names that differ only in punctuation export to the same file name; the browser numbers the second.
Where: `ui/src/features/dashboard/edit-model.ts`, `download.ts`, `wire.ts`; tests `edit-model.test.ts`, `download.test.ts`, `edit-tools.test.tsx`; `ui/e2e/dashboard-edit.spec.ts` asserts the download.
Revisit when: a shortcuts setting is added, or layouts can be imported.
