# 0077. The compose password lives in `~/.config/command-center/compose.env`, outside the repo

Status: accepted

Context: `docker-compose.yml` requires `POSTGRES_PASSWORD` (`${POSTGRES_PASSWORD:?...}`). Compose reads a `.env` next to the compose file on its own, so the password had been kept in a repo-root `.env`. That left a secret in the working tree, where a commit, a project-folder backup or a coding agent can reach it, and the agent sandbox denies reads of `.env` (it made pytest fail during collection). The project owner moved the file out of the repo.
Decision: the password file is `~/.config/command-center/compose.env` (directory mode 700, file mode 600), holding `POSTGRES_PASSWORD=<random hex>` and optionally `CC_TZ`. Every compose command passes `--env-file ~/.config/command-center/compose.env` (`build` too, because compose reads the password while parsing the file). `docker-compose.yml` is unchanged in this respect: the password stays required and has no default. `docs/distributed-mode.md` has the creation steps and the reason.
Alternative: (a) Keep a repo-root `.env`, git-ignored: still in the working tree, and still denied to the sandbox. (b) A default password in the compose file: a guessable secret on every install; it would also defeat the "required, no default" rule. (c) Docker secrets or an external secret manager: more moving parts than a single-machine stack needs. (d) Export the variable in the shell each time: works (and wins over the file) but is easy to forget and ends up in shell history.
Reason: the secret sits outside anything the repo, its tooling or its agents touch, and a command given no password still fails loudly. The app needs no change (checked): `Settings` in `config.py` sets no `env_file`, so the app never reads any `.env` file, in the repo root or elsewhere; it reads real environment variables only (`CC_` prefix, plus `DATABASE_URL`). The tests pass `_env_file=None` as a guard. `Settings` uses `extra="ignore"` and `POSTGRES_PASSWORD` has no `CC_` prefix, so a compose-only variable can neither be read by it nor break startup. Inside the containers the password reaches the app only through `DATABASE_URL`, which compose builds from it. `.dockerignore` also excludes `.env` and `.env.*` from the image. `.gitignore` ignores `.env` and `.env.*` (except `.env.example`) as a second guard.
Where: `docs/distributed-mode.md` (How to run, Useful commands, Gmail workaround), the header comment of `docker-compose.yml`. Tests: `test_compose_password.py` (every `${POSTGRES_PASSWORD...}` is `:?`, no `env_file`), `test_compose_file.py` (no literal password).
Revisit when: a secret manager is adopted for the stack, or the stack moves off a single machine.
