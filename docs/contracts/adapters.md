# Contract: adapters

Concrete integrations. Each implements a core port; each vendor SDK is imported in exactly one file.

## Rules for every source adapter
1. Implement `SourceAdapter` (`core/ports.py`): `name`, `async validate(creds)`, `async fetch(creds, window)`.
2. Raise `AuthExpired` (credentials rejected: the user reconnects), `TransientError` (timeout, rate limit, 5xx: retry later) or `FatalError` (malformed data, unsupported request: do not retry). Translate vendor errors into these; never let an `httpx` or SDK exception escape.
3. Leave `Event.urgency` at 0. `AgendaService` scores at read time from `core.scoring.urgency`; a stored score would go stale.
4. Use `httpx` with an explicit timeout on every call. Tests mock it with `respx` fixtures and use made-up credentials; no real credentials, accounts or network.
5. Every user-supplied URL (a Canvas base URL, a pasted iCal feed) goes through `core.urlcheck.require_https_public`, and its host through `await net_guard.ensure_public_host(host)`, before any request is sent. Both raise `ValueError`; map it to `FatalError`. `ensure_public_host` can also raise `TransientError` on a lookup timeout; let that propagate.
6. No credentials in logs, exception messages or `Event.raw`. `raw` holds the source's public item fields only, never tokens, auth headers or request URLs that embed a key.
7. Each vendor SDK is imported in exactly one file, the one named for it in the import-linter contracts in `pyproject.toml` (see `docs/MAP.md`). A source whose SDK has no named file needs a decision first; do not add one to `pyproject.toml` from an adapter task.
8. Adapters import `core` only: no services, storage, api or app. Composition roots build them.
9. Every `Event` sets `start` or `due`. An undated event never appears in any window, and the sync cannot prune it (decision 0028).
10. `fetch` never returns a partial result; raise instead. The one explicit exception is Canvas: a course whose assignments call returns 401 contributes no assignments (Canvas answers 401 for a course the user may not read, and failing the sync would block every other course; decisions 0041, 0046). Its planner items and calendar events are still returned, because the user can see them. `SyncService` replaces the source's stored events in the window with whatever `fetch` returns, so a short list deletes the missing events (for a skipped course, its stored assignments). It must return every item `EventStore.query(window)` would match: spans by overlap (including ones that began before `window.start`), points by `start` else `due` in the half-open window; otherwise the sync deletes the items it left out.

## Behaviour (built)
- `keyring_store.KeyringSecretStore` implements `SecretStore` over the OS keychain (the only importer of `keyring`). It keeps one keychain entry per `(user_id, source)` under the service name `command-center`: a JSON object of key to value. `set` reads, updates one key and rewrites the entry under a process-wide lock, which `delete` also takes, so threads in one process cannot lose each other's updates; a second process is not covered. Decision: docs/decisions/0012 (supersedes the adapter clause of 0010). `status` derives from `core.schema.secret_status`, so `last4` is `None` below 8 characters. `delete` of a missing entry is a no-op. Failures raise `core.errors.SecretStoreError`, which services catch directly (decision 0024). Values are never logged, returned by `status`, or put in an error message.
- `SecretStoreError` is raised when the keychain cannot be used: no backend (`NoKeyringError`: "No OS keyring backend is available"), another `KeyringError` (the message carries only the exception class name), or a stored entry that does not parse (corrupt; the entry is not echoed). None of these chain the underlying exception. A corrupt entry keeps raising from `get`, `status` and `set` until the source is deleted: `delete(source)` removes it without parsing it, after which the keys can be entered again.
- `net_guard.ensure_public_host(host, timeout=5.0)` resolves `host` with `getaddrinfo` in a worker thread, waiting at most `timeout` seconds (`asyncio.wait_for`; not a config field), and passes every address through `require_https_public` (IPv6 in brackets, so `https://[::1]/`). It raises `ValueError` if the host does not resolve, resolves to nothing, or any address is not public; messages never echo the host or addresses. If the lookup times out it raises `core.errors.TransientError("host lookup timed out")`, which adapters let propagate (a retry may succeed), unlike the `ValueError`, which they map to `FatalError`. A thread cannot be cancelled, so the lookup thread may outlive the timeout and finish in the background; its result is discarded. Limitation: this checks the answer at check time only. A hostile DNS server can answer differently when the HTTP client connects (DNS rebinding), so this narrows SSRF but does not close it; pinning the connection to the checked address is not done.
- `system_clock.SystemClock` implements `Clock`: `datetime.now(UTC)`.
- `summary_gemini.GeminiSummaryProvider(secrets, *, model="gemini-3.5-flash-lite", client_factory)` implements `SummaryProvider` (the only importer of google-genai). The key is `secrets.get("gemini")["api_key"]`, read on each call; a missing key or unavailable store is a `SummaryProviderError`. Structured output: `response_mime_type="application/json"` with `DailySummary` as the schema, parsed back through the model. HTTP timeout 30 s. A 429 is `SummaryRateLimited`; 401/403 `SummaryProviderError("Gemini rejected the API key")`; other API errors `SummaryProviderError("Gemini request failed (<code>)")`; network failures and malformed output are `SummaryProviderError`. Messages are fixed text: never the key, the prompt or the SDK's message, and the SDK exception is not chained. A reply that is not JSON (`UnknownApiResponseError`, a `ValueError`, whose message embeds the body) is `SummaryProviderError("Gemini returned a malformed response")`. Both the async and the sync client are closed after each call. Decision: 0036.
- `summary_gemini.GeminiIntegration(*, model="gemini-3.5-flash-lite", client_factory, timeout=15.0)` implements `IntegrationAdapter` (name `gemini`, same file and SDK as the provider). `validate({"api_key": ...})` makes one `count_tokens` call (no generation, so no quota spent on output) with the 15 s timeout (SDK `HttpOptions` and `asyncio.timeout`). A missing or blank key is `ok=False` without a call; 400, 401 and 403 are `ok=False` "Gemini rejected the API key" (Google answers an unknown key with 400); other 4xx `ok=False` "Gemini request failed (<code>)"; 429, 5xx, a timeout, a network failure and a non-JSON reply are `TransientError`. Messages are fixed text, never the key or the SDK message, and the SDK exception is not chained; both clients are closed after each call. `SettingsService` redacts the message again. Decision: 0058.
- `summary_ollama.OllamaSummaryProvider(*, model="llama3.2", base_url="http://localhost:11434")` implements `SummaryProvider` over httpx: `POST /api/generate` with `format: "json"`, `stream: false`, 120 s timeout. 429/503 is `SummaryRateLimited`; 404 (model not pulled), other 4xx/5xx, timeouts, connection errors and malformed replies are `SummaryProviderError` with fixed messages. The URL is fixed and local, not user-supplied, so the URL guard does not apply.
- `ical_events` (pure; no I/O): `parse_calendar(text)` and `events_in_window(calendar, source, scope, tz, window, fetched_at, extra_raw)` turn iCalendar text into `event`s: recurrence expanded (EXDATE, RECURRENCE-ID overrides, DST), floating times and all-day dates placed in `tz` (all-day = local midnight to next local midnight), CANCELLED and DTSTART-less items dropped, kept by the store's rule (spans by overlap, points by `start` in the half-open window). Both raise `ValueError` for text that is not iCalendar or whose rules cannot be expanded, with a message that never quotes the input. Decisions: docs/decisions/0030, 0031.
- `caldav_apple.AppleCalendarAdapter(tz, clock, session_factory=open_session)`: name `apple_calendar`, creds `username`, `app_password`, server `caldav.icloud.com`. Blocking caldav calls run in `asyncio.to_thread`, 10 s timeout. `validate` = log in + list calendars; `fetch` = every calendar's `search(start, end, event=True, expand=True)`, with the window padded by 2 days each side because the server matches floating and all-day items in the request's zone, through `ical_events`, which filters exactly. A rejected login is `AuthExpired`; a network, server or unexpected vendor error is `TransientError`; an item that does not parse is `FatalError`. Messages quote no credential and the underlying exception is not chained. Any calendar failing raises; nothing partial is returned.
- `ical_feed.IcalFeedAdapter(tz, clock)`: name `learningsuite`, creds `urls` (newline-separated; one feed per course). Each URL goes through `require_https_public` then `ensure_public_host` before a request; redirects are not followed (a 3xx is `FatalError`); 5 MB cap (declared length and while streaming), 10 s timeout (per call and overall), in-memory ETag cache keyed by a hash of the URL and pruned to the configured feeds. Every message names the feed number (`Feed 2: ...`), never the URL, which is a secret (decision 0005). `validate` returns `ok=False` for a rejected or malformed feed and lets a `TransientError` propagate; `fetch` raises on any failing feed and with no URLs configured. Items are kind `event` (decision 0030).
- `canvas.CanvasAdapter(clock, sleep=asyncio.sleep, lookback_days=7)` (`canvas.py` is the adapter class; transport in `canvas_client.py`, response models in `canvas_models.py`, reads and `Event` mapping in `canvas_fetch.py`; decision 0081): name `canvas`, creds `base_url`, `token` (bearer). The base URL goes through `require_https_public`, its path is dropped, and `ensure_public_host` runs before any request; a bad URL is `FatalError`, a lookup timeout `TransientError`, missing creds `AuthExpired`. Redirects are not followed, every call has a 15 s timeout, and a `Link` rel="next" to another host, scheme or port is `FatalError` (the token is never sent there); lists use `per_page=100`, follow `Link` only, and stop at 200 pages. `validate` = `GET /api/v1/users/self`: 401 gives `ok=False` "Token rejected", every other failure (network, 5xx, bad URL, lookup timeout) an `ok=False` message; it never raises. `fetch` reads active courses, then each course's assignments (`include[]=submission`) one after another, then planner items, then calendar events (the personal calendar plus course calendars ten codes at a time), and keeps what the store's window rule would match. Planner and calendar requests send `start_date = window.start - lookback_days` (negative counts as 0) so events that began earlier and still run are returned, then trim locally (decision 0042); a running event that began more than `lookback_days` before the window can still be missed. 403 or 429 is retried 3 times after 2, 4, 8 s (`Retry-After` wins, capped at 30 s), then `TransientError`; a low `X-Rate-Limit-Remaining` pauses 2 s; 401 is `AuthExpired` (on the course list, planner and calendar calls; in `validate`, a 401 on `/users/self` is `ok=False` instead), except that a 401 on any page of one course's assignments skips that course's assignments (including those of pages already read) and logs its id and the error class, never a URL; the course's planner items and calendar events are still returned (decisions 0041, 0046); 5xx, timeouts and network errors are `TransientError`; other statuses and malformed JSON are `FatalError`. Any other failure raises, so nothing partial is returned. Assignments are kind `assignment` (`due`, status "done" if submitted, graded or pending review, else "open", id from `course:assignment`); planner items and calendar events are kind `event`, except that a planner item with the same course (read from `/courses/<id>` in its link), title and start as an assignment's `course_id`, title and `due` is that assignment's copy (a graded quiz or discussion) and is left out; a planner item with no course in its link matches on title and start alone, and every planner event carries `raw["course_id"]` when its link names a course (decisions 0094, 0095). Out of v1: grades, announcements. Decisions: docs/decisions/0032, 0033, 0041, 0042, 0046, 0094, 0095.
- `gmail.GmailAdapter(clock, *, vip_senders=(), muted_senders=(), service_factory, sign_in, sign_in_timeout=180)`: name `gmail`, scope `gmail.readonly`, creds `client_json` (the pasted Google OAuth desktop-client file) and `refresh_token`. Setup: docs/gmail-setup.md. Only importer of googleapiclient and google_auth_oauthlib; it also imports google-auth (decision 0043). Credentials are rebuilt from the two values on every call and no access token is stored; every call has a 15 s timeout. `validate` never raises: no client file or a client file that is not a Desktop client gives `ok=False`; no `refresh_token` runs `InstalledAppFlow.run_local_server(port=0, timeout_seconds=180)` in a thread under a 180 s `wait_for` (timeout gives `ok=False` "Sign-in timed out"; success gives `ok=True` with `updated_creds={"refresh_token": ...}`); otherwise `users.getProfile`. A rejected token (`RefreshError`, 401) is `AuthExpired` (the UI shows Reconnect; tokens last 7 days while the app is unverified, decision 0003); missing creds in `fetch` is `AuthExpired`; 429, 5xx, a deleted thread (404), throttling 403s, network failures and a retryable `RefreshError` are `TransientError`; other 4xx and malformed replies are `FatalError`. Messages are fixed text. `fetch` lists `threads.list` with `q="newer_than:14d -category:promotions -category:social -category:updates -category:forums"` (100 per page, at most 20 pages), then `threads.get(format=metadata)` for From/To/Cc/Subject/List-Unsubscribe/List-Id/Precedence/Auto-Submitted, and returns one `email` Event per thread still owed a reply: `start` = last message `internalDate`, `title` = trimmed subject, `status` `owed` or `overdue` (waiting over 2 days), `link` = the thread, `raw` = `{"sender": display name, "snippet": ...}`. Any failed thread fetch raises. Rules (VIP, muted, bulk, drafts) and their reasons: decision 0044; they live in `gmail_mail.py`, which imports no SDK.
- `weather.WeatherAdapter(clock, *, client=None)`: name `weather`, creds `latitude`, `longitude`, Open-Meteo `v1/forecast` over httpx (10 s timeout, Fahrenheit, mph, `timezone=auto`, 7 days). One `weather` Event per day with `start` at that local midnight and a title such as "High 54°, low 38°, 20% rain", in the window only. The parsed Events are cached per location for 20 minutes of `Clock` time (a hit makes no request; failures are not cached). 429, 5xx and network errors are `TransientError`; bad coordinates, other statuses and malformed replies are `FatalError`; `validate` never raises. Decision: 0045.

- `inprocess_queue.InProcessQueue(clock, rng, *, policy, visibility_timeout)` and `queue_redis.RedisStreamsQueue(client, clock, rng, *, prefix="cc", policy, visibility_timeout)` implement `JobQueue` (the only importer of `redis` is `queue_redis.py`; `RedisStreamsQueue.from_url(url, clock, rng, ...)` builds the client for composition roots). Both run `tests/test_job_queue_contract.py`; the Redis cases run only when `CC_TEST_REDIS_URL` is set (CI job `integration`, not required, which also starts Postgres; decision 0083). Semantics (decision 0047): at-least-once; one lane, first delivery in publish order; `consume` waits at most `block_ms`; an unacked job returns after the visibility timeout with `attempt + 1`; `fail` requeues after `RetryPolicy.delay` or dead-letters when attempts are used up (a timeout on the last attempt also dead-letters); `ack`/`fail`/`dead_letter` of a job not in flight are no-ops (`dead_letter(job, reason)` dead-letters the held job at once, decision 0071); reasons are trimmed to 300 characters. Defaults: 5 attempts, 5 s base, factor 2, cap 5 min, visibility 5 min (0048). Dead letters are kept and listed, never replayed (0049). Redis keys: `{prefix}:jobs` (stream), `{prefix}:jobs:delayed` (sorted set), `{prefix}:jobs:dead` (stream), with the prefix in braces (a hash tag, `{cc}:jobs`) so they share a cluster slot; an entry that cannot be parsed is acked, deleted and logged at ERROR (0049); retries are moved onto the stream at the start of the next `consume`; an acked entry is deleted, so use one consumer group. Entry ids are held in the consuming process. The in-process queue ignores `group` and `consumer` and must be used from one event loop. File name differs from the task card: 0050.
- `json_log`: `JsonFormatter` (one JSON line per record; only `correlation_id`, `job_id`, `job_kind`, `source`, `attempt`, `delay_seconds`, `reason`, `consumer`, `error_class` are emitted besides time, level, logger and message; an exception is its class name only), `job_fields(job)` (the `extra` dict for a job) and `configure_json_logging(level, stream)`, which only composition roots call (a test enforces it). `app.main()` and `workers/__main__.main()` call it, and so does the scheduler role. `error_class` is the exception's class name, logged on retry, give-up and dead-letter in place of the exception's message. Decisions: 0051, 0070.

- `inprocess_reports.InProcessReportStream(clock, *, visibility_timeout, max_deliveries=5)` and `queue_redis.RedisReportStream(client, clock, *, prefix, visibility_timeout, max_deliveries=5)` implement `ReportStream` with the delivery rules of the queues (at-least-once, redelivery after the visibility timeout, a report delivered more than `max_deliveries` times without an ack is dead-lettered with a fixed reason, `dead_letter` trims reasons to 300 characters). Redis keys `{prefix}:reports` and `{prefix}:reports:dead`; `RedisReportStream.from_url` builds the client. `tests/test_report_stream_contract.py` runs both; the Redis cases need `CC_TEST_REDIS_URL`. Decision 0071.
- `file_secret_store.FileSecretStore(directory)` implements `SecretStore` over `<directory>/secrets.json` (`{user: {source: {key: value}}}`): directory 0700, file written 0600 by temporary file and atomic rename, `flock` on `secrets.json.lock` for writers in other processes, refuses to read a file with group or other permission bits and a corrupt file (`SecretStoreError`, no content in the message). `secret_backend.build_secret_store(backend, data_dir)` picks it for `file` and the keyring store for `keyring` (the default). For containers only; Gmail's browser sign-in cannot run there. Decision 0073.
- `source_registry.build_source_adapters(tz, clock)` builds the five source adapters (the api and every worker use it); `system_rng.SystemRng` and `system_ids.UuidIdSource` (`new_id()` is a `uuid4` hex) are the real `Rng` and `IdSource`.
- `system_tokens.SystemTokenSource.new_token(num_bytes)`: URL-safe random text from `secrets.token_urlsafe`; fewer than 16 bytes is a `ValueError`. The real `TokenSource`.
- `menubar_rumps.RumpsMenuBar(*, title, login_enabled, on_open, on_pair, on_toggle_login, on_tick, on_quit, tick_seconds)`: the macOS menu bar (only importer of `rumps`). Entries Open, Pair phone, Launch at login (a check mark), Quit; a timer calls `on_tick` and shows the title it returns. It decides nothing; `desktop/main.py` supplies every callback. macOS only (the `desktop` extra).
