# Contract: storage

Persistence. Implements storage ports from core; SQLAlchemy lives here.

## Behaviour
- `sqlite.SqliteEventStore` implements `EventStore` (sync SQLAlchemy 2). `create_event_store(database_url)` is the factory: it creates the parent directory of a SQLite file, creates the tables if missing and returns the store; `close()` releases the pool. Any SQLAlchemy URL works, so Postgres needs no code change (its driver is the optional `distributed` extra).
- Table `events`, primary key `(user_id, id)`. Columns mirror `Event`; `raw` is JSON (written through `model_dump(mode="json")`, so non-JSON values come back as their JSON form). Datetimes are stored in UTC and returned timezone-aware in UTC (equal to the instant written, not the zone it was written in). `anchor` is an indexed column holding `start`, else `due`.
- `upsert` merges by `(user_id, id)` in one transaction; a repeated id in a batch keeps the last event; an event whose `user_id` differs from the argument raises `ValueError` before anything is written. `query` follows the matching rules in `docs/contracts/core.md` exactly (time is `start` else `due`; a span, `end` after the time, matches on overlap; a point matches in the half-open window; undated events never match; ordered by time then id). Both stores run the shared suite `tests/test_event_store_contract.py`.
- `replace(source, window, events)` runs in one transaction: it deletes the user's rows of that `source` that match `window` (the same `_matches_window` predicate as `query`, so undated rows are never deleted and rows outside the window are kept), then merges `events` like `upsert`. A failure while writing rolls the delete back, so the old events remain. An event whose `user_id` or `source` differs from the arguments raises `ValueError` before anything is written. It returns the distinct events written. `delete_source(source)` deletes every row of that source and user, dated or undated, and returns the number deleted. Both stores run `tests/test_event_store_replace_contract.py`; SQLite's rollback is covered by `tests/test_sqlite_event_store_replace.py`. Decision: 0028.
- The URL comes from `config.Settings.database_url` (env `CC_DATABASE_URL`, also `DATABASE_URL`; default `sqlite:///<data_dir>/command_center.db` with `data_dir` `~/.command-center`). Composition roots pass it in; storage never reads the environment.
- The engine is created with `hide_parameters=True`: a failed statement's error text names the SQL but not the bound values, so event titles and `raw` fields never reach an exception message or a log (decision 0027).
- Ordering by id uses the database's collation. SQLite's default is bytewise, which equals the in-memory fake; a Postgres deployment must use a `C` collation (or the suite will tell us).

- `sqlite_summary.SqliteSummaryStore` implements `SummaryStore` (sync SQLAlchemy 2); `create_summary_store(database_url)` mirrors `create_event_store` (creates the file's directory and the table, `hide_parameters=True`). Table `summaries`, primary key `(user_id, day)`, `summary` holds the `DailySummary` as JSON text. `put` replaces the row; `latest_before(day)` is the row with the greatest `day` strictly before `day` for the user, not the last written; a row that no longer parses reads as missing. Decisions: 0035, 0040.

- `sqlite_devices.SqliteDeviceStore` implements `DeviceStore`; `create_device_store(database_url)` mirrors the other factories (`hide_parameters=True`). Tables `pairing_tokens`, `devices` and `device_credentials(token_hash PK, device_id, kind, expires_at, superseded)`; only SHA-256 hex digests are stored, timestamps are fixed-width UTC ISO strings. A pairing token is taken by one `DELETE ... RETURNING`, a refresh credential is rotated by one `UPDATE ... RETURNING`; reads compare digests with `hashes_match`. Both the fake and SQLite stores run `tests/device_store_contract.py`. Decision 0057.

- `sqlite_states.SqliteSyncStateStore` implements `SyncStateStore`; `create_sync_state_store(database_url)` mirrors the other factories (`hide_parameters=True`). Table `sync_states`, primary key `(user_id, source)`, `state` holds the whole `SyncState` as JSON text (`at` is inside it, an ISO instant with offset). `put` replaces the state of the row but keeps its `generation` (a new row gets 0). Column `generation INTEGER NOT NULL DEFAULT 0`, the generation the row was written under, stamped by the report sink (decisions 0071, 0075). `ensure_state_schema(engine)` runs in the factory: it creates the table, or adds the column to a table from before 0075 with `ALTER TABLE ... ADD COLUMN` (SQLite and Postgres; a lost race with another process re-checks and carries on) and stamps the existing rows with their source's current generation (0 if there is none). Session-level helpers `put_state`, `read_state` and `delete_state` run inside a caller's transaction, for the sink. In compose the api and the normalizer create tables on the same Postgres, so the normalizer starts after the api is healthy.

- `sqlite_generations.SqliteGenerationStore` implements `GenerationStore`; `create_generation_store(database_url)` mirrors the other factories (`hide_parameters=True`). Table `source_generations(user_id, source, generation)`, primary key `(user_id, source)`. `bump` is one `UPDATE ... SET generation = generation + 1 ... RETURNING` (SQLite 3.35+ and Postgres); the first bump of a source inserts the row with 1, and a loser of the insert race (`IntegrityError`) updates the row the winner made. The row is never deleted: purging a source's state must not reset its counter. Both the in-memory fake and this store run `tests/test_generation_store.py`. `lock_generation(session, source, user_id)` (for the sink) inserts the row at 0 if missing (`ON CONFLICT DO NOTHING`, SQLite and Postgres), then runs a no-op `UPDATE ... RETURNING generation`, which returns the number and holds the row until the transaction ends; a concurrent `bump` waits for it. Decisions 0074, 0075.

- `sqlite_sink.SqliteReportSink` implements `ReportSink` over one engine; `create_report_sink(database_url)` opens it and calls `ensure_schema(engine)`, which creates or upgrades the events, generation and state tables (in that order). Events, `sync_states` and `source_generations` must be in one database. `apply` and `purge_stale` start with `lock_generation`, so the generation check and every write are one transaction; `replace_events` and `delete_source_events` (the helpers `SqliteEventStore.replace` and `delete_source` also use) do the event writes. Behaviour of the port is in `docs/contracts/core.md`; tests: `test_report_sink.py`, `test_normalizer_atomic.py`, `test_state_generation_column.py` (SQLite always, Postgres with `CC_TEST_POSTGRES_URL`). Decision 0075.

## Not built yet
- General schema migrations: tables are created if missing and never altered, except for the one `sync_states.generation` column that `ensure_state_schema` adds (decision 0075). Also a cache of fetched items with per-source last-sync times.
- Never stores secrets (those are in the keychain) or email bodies.
