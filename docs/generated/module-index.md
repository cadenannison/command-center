# Module index

Generated by `mise run gen:build` from the module docstrings under `src/command_center/`. Do not edit.

One line per module: its first docstring sentence. Use it to find the file you need instead of listing or opening folders. Layer rules and import boundaries: `docs/MAP.md`.

## (root)
- `app.py`: Composition root for the API process: wires concrete infrastructure.
- `config.py`: Runtime settings from the environment (CC_ prefix).

## adapters/
- `caldav_apple.py`: iCloud calendars over CalDAV with an app-specific password (the only importer of `caldav`).
- `canvas.py`: Canvas LMS source: assignments, planner items and calendar events for the active courses.
- `canvas_client.py`: Canvas REST transport: bearer auth, Link pagination, rate-limit backoff, error translation.
- `canvas_fetch.py`: Canvas reads: active courses, assignments, planner items and calendar events as `Event`s.
- `canvas_models.py`: The slice of the Canvas REST responses the adapter reads, and the parse that guards it.
- `chat_http.py`: Shared plumbing of the two httpx chat providers: the URL guard at call time and error mapping.
- `chat_ollama.py`: Ollama chat provider: the local option.
- `chat_openai.py`: OpenAI-compatible chat provider: llama.cpp, LM Studio, vLLM, OpenRouter and OpenAI itself.
- `file_secret_store.py`: SecretStore over a 0600 JSON file, for containers where no OS keychain exists (decision 0073).
- `gmail.py`: Gmail source: threads that probably still owe the user a reply.
- `gmail_mail.py`: Gmail response shapes and the owed-reply heuristic.
- `http_cap.py`: The reply-size cap shared by the chat providers and the city search (decisions 0222, 0246).
- `ical_diagnose.py`: Counts-only diagnosis of the stored iCal feeds ("why does LearningSuite return 0 items").
- `ical_diagnose_report.py`: The counts-only report of one feed, its conclusion line and its text (see ical_diagnose).
- `ical_events.py`: Shared iCalendar parsing for the CalDAV and iCal-feed adapters: text in, Events out.
- `ical_feed.py`: Pasted iCal feed URLs (BYU LearningSuite, one per course) as a source adapter.
- `inprocess_queue.py`: In-process JobQueue for single-process mode and tests.
- `inprocess_reports.py`: In-process ReportStream for tests and hermetic chaos runs.
- `json_log.py`: Structured JSON logging that carries a job's correlation id.
- `keyring_store.py`: SecretStore over the OS keychain.
- `log_redaction.py`: Keeps the city search text out of uvicorn's access log (decision 0180).
- `menubar_rumps.py`: The macOS menu-bar shell.
- `net_guard.py`: DNS-time SSRF guard: a public-looking name must not resolve to a private address.
- `queue_redis.py`: Redis Streams JobQueue for distributed mode (the only importer of redis).
- `secret_backend.py`: Chooses the SecretStore: the OS keychain (default) or a 0600 file (containers).
- `source_registry.py`: The five sources, built once for every composition root that needs them.
- `summary_gemini.py`: Gemini summary provider.
- `summary_ollama.py`: Ollama summary provider: the local option, nothing leaves the machine.
- `system_clock.py`: The real Clock, for composition roots and adapters.
- `system_ids.py`: The real IdSource: random UUIDs.
- `system_rng.py`: The real Rng: the operating system's random source.
- `system_tokens.py`: The real TokenSource: the operating system's cryptographic random source.
- `weather.py`: Weather source: one Open-Meteo forecast Event per day (decision 0045).
- `weather_geocode.py`: City search over Open-Meteo's geocoding API (decision 0180).

## api/
- `agenda.py`: Read routes: events in a window, the day/week/month agenda and the attention list.
- `auth.py`: Who needs a token: the Host header decides.
- `chat_routes.py`: Read-only chat about the agenda: loopback only, 404 while chat is off (0160-0169).
- `deps.py`: Request-scoped access to the wired services.
- `errors.py`: Error bodies and the handlers that keep request content (credentials) out of them.
- `factory.py`: Builds the FastAPI application around a service container.
- `geocode_routes.py`: City search for the weather form: candidates for a name, never a pick (decision 0180).
- `health.py`: Liveness endpoint.
- `items.py`: Check-off, notes, local tasks and the day's history (decisions 0120, 0123, 0125, 0126).
- `pairing_routes.py`: Phone pairing and device management under /v1.
- `policy.py`: Pure request rules for `DeviceAuthMiddleware`: what a paired phone may call, and the JSON check.
- `settings.py`: Settings routes.
- `summary_routes.py`: The opt-in daily summary, always mounted; 404 while summaries are off (decisions 0037, 0053).
- `sync.py`: Manual sync trigger.

## core/
- `chat.py`: Read-only AI chat: turn capping, the redacted context body and the trusted system prompt.
- `errors.py`: Failure classes for source adapters.
- `geocode.py`: City search building blocks: what a candidate place is and what a query may look like (0180).
- `hosts.py`: Host-header classification: loopback, an allowed remote name, or rejected.
- `jobs.py`: Background job model: a unit of work for a JobQueue and the record of one that gave up.
- `ledger.py`: The item ledger's pure parts: local tasks, notes, history and marks laid over events.
- `pairing.py`: Phone pairing: token hashing, credential models, device names and the failure limiter.
- `ports.py`: Ports the pure core depends on.
- `priority.py`: Priority 1-10 derived from the 0-100 urgency score.
- `redact.py`: Redaction for AI-summary input.
- `resilience.py`: Retry backoff and a circuit breaker, both pure: time and randomness are passed in.
- `schema.py`: Shared building blocks: the Event every source normalises into, plus small result types.
- `scoring.py`: Deterministic urgency scoring (0-100) and its reason.
- `summary.py`: Opt-in daily summary: the result model, the redacted prompt and a provider-free fallback.
- `sync_state.py`: The last sync result of one source: what the settings view shows and workers record.
- `urlcheck.py`: SSRF guard for user-supplied URLs.
- `windows.py`: Day, week and month windows in the user's timezone, built from local midnight (DST-safe).

## desktop/
- `events_client.py`: Reads upcoming items from the menu-bar app's own server over loopback HTTP.
- `launch_agent.py`: The LaunchAgent that starts the menu-bar app at login.
- `main.py`: Composition root for the macOS menu-bar launcher: starts the server, shows the next deadline.
- `menu_title.py`: The menu-bar title: the next open deadline, worded for a glance.
- `server_process.py`: The server the menu-bar app owns: the command to run it and a small process handle.

## pairing/
- `qr.py`: The pairing QR code: a small JSON payload drawn as an SVG, with no imaging library.

## services/
- `agenda.py`: Reads events back out, scored against the current time and ordered by when they happen.
- `chat.py`: Read-only chat about the user's agenda.
- `chat_settings.py`: The stored chat settings: opt-in, provider and what context may be sent (decisions 0160-0166).
- `container.py`: The set of services a process serves; built by a composition root, consumed by the api.
- `credential_fields.py`: Which credential keys are secret, per source: the one place that decides (decision 0100).
- `errors.py`: Failure classes the services raise for their callers (the api maps them to responses).
- `geocode.py`: City search for the weather form: a rate limit and redacted failures around a Geocoder (0180).
- `horizon.py`: The span of time the app syncs and watches for attention items.
- `items.py`: What the user does to items: check off, notes, their own tasks, and the day's history.
- `models.py`: Result types the services return.
- `pairing.py`: Phone pairing: a one-time token becomes a device credential that rotates on every refresh.
- `queued_sync.py`: The api's view of syncing in distributed mode: queue the work, read what the normalizer wrote.
- `scheduler.py`: Keeps the sources fresh: one sync of everything at startup, then one per interval.
- `settings.py`: Connects and disconnects sources.
- `setup_checklist.py`: The setup checklist of the settings page: each source's state and how long ago it last synced.
- `summary.py`: The opt-in daily summary: cache, provider, fallbacks.
- `summary_control.py`: The stored AI-summary opt-in and provider choice, and the SummaryService built from them.
- `sync.py`: Pulls each source's items into the event store and remembers how the last attempt went.
- `sync_control.py`: What the settings service, the routes and the scheduler need from "the sync" (decision 0074).

## storage/
- `sqlite.py`: SQLAlchemy EventStore.
- `sqlite_app_settings.py`: SQLAlchemy AppSettingStore: a small key-value table, one row per user and key.
- `sqlite_completions.py`: The completions table: append-only entries, one per completion (decision 0131).
- `sqlite_devices.py`: SQLAlchemy DeviceStore: pairing tokens, paired phones and their credential hashes.
- `sqlite_generations.py`: SQLAlchemy GenerationStore: one counter per user and source.
- `sqlite_items.py`: SQLAlchemy ItemLedger: notes, check-offs, history and the user's own tasks (decision 0120).
- `sqlite_ledger.py`: What the sources did to items, kept after the items are gone: the sync side of the ledger.
- `sqlite_ledger_tables.py`: The ledger's two tables (decisions 0120, 0131).
- `sqlite_sink.py`: SQLAlchemy ReportSink: a report's events, state and generation check in one transaction.
- `sqlite_states.py`: SQLAlchemy SyncStateStore: one row per user and source.
- `sqlite_summary.py`: SQLAlchemy SummaryStore: one row per user and day.
- `sqlite_types.py`: Column types shared by the SQLAlchemy tables.

- `cards.py`: View models for the settings page.
- `chat_page.py`: The /chat page: ask the assistant about the agenda.

- `summary.py`: The AI summary card on Today: its states and the routes that change or refresh it.
- `task_form.py`: Turns the New task and Edit task forms into core inputs.
- `views.py`: Turns scored events into what the templates draw.

## workers/
- `__main__.py`: Composition root for distributed mode: one process per role (decision 0070).
- `normalizer.py`: Applies sync reports to the stores: the one writer of what workers fetch (decision 0071).
- `sync_worker.py`: Consumes sync jobs for one source and publishes what the adapter fetched (decision 0070).
